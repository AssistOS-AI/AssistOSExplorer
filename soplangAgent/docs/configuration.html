Manifest and Environment

The agent follows the Ploinky manifest standard and relies on a minimal set of environment variables for runtime behavior.

Manifest

Main configuration file: soplangAgent/manifest.json.

{
  "lite-sandbox": true,
  "container": "docker.io/assistos/ploinky-node@sha256:accd925fcbf460c1f4c7a5cd9e2d46539c615bbfad2e896cabb7556d8050a669",
  "profiles": {
    "default": {
      "env": ["ACHILLES_DEBUG"]
    }
  }
}

The lite-sandbox flag asks Ploinky to prefer the host sandbox runtime when available. The container field remains the fallback image used when host sandboxing is disabled, and profiles.default.env declares forwarded environment variables used by the agent.

Environment Variables

Variable Usage
ACHILLES_DEBUG Enables detailed debug logging via plugins/debugLogger.mjs.
PERSISTENCE_FOLDER, LOGS_FOLDER, AUDIT_FOLDER Resolved by soplang-tool.sh below $HOME/.soplang, which is inside the agent's Ploinky-mounted persistent home. Explicit values remain supported. Both last-tool.log and achilles-debug.log are written under LOGS_FOLDER; neither is written beside source code or in the current directory.
SOPLANG_STATE_ROOT Optionally overrides the common SOPLang state root used for storage, logs, and audit data.

Plugin and Command Registration

At invocation time, the wrapper registers SOPLang plugins and then loads the project plugin targeted by the requested tool. During builder initialization, custom commands are registered (load, createJSCode, store). The Achilles bridge and its skills are initialized only for execute_skill; read-only builder tools do not start Achilles or an LLM workflow.

The Achilles bridge supplies the complete local logger interface, including debug() and error(), so generator failures retain their original cause. Model selection remains owned by the runtime-provided Achilles library and Soul Gateway; the agent does not maintain local model aliases.

Local Skills Folder

Local packages under soplangAgent/skills/ can be discovered and registered as commands through Achilles bridge. Explorer invokes the declared MCP tools; local skill registration does not itself create an Explorer workflow.

This keeps future extension points ready without changing MCP API contracts.

Test Validation

Repository validation is executed with npm test from soplangAgent/. Code changes are considered complete only after this test command passes.
