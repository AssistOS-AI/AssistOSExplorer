# Deployment helper dependencies

The QA shutdown, recovery and Soul settings helpers add no npm packages. They use Node.js built-ins and the exact deployed Ploinky checkout. The ordinary helpers require the Node runtime already supplied by the deployment host and Box. Soul snapshot reconciliation additionally requires `node:sqlite` with `DatabaseSync` and `backup`; it fails with `SOUL_SQLITE_UNAVAILABLE` before opening a database or creating output if those APIs are absent. Use a compatible reviewed Node runtime for that optional operation. Do not install packages during recovery startup.

Recovery reuses the host's Git, Podman or Docker, sudo, GNU `cp` and `cmp`, and util-linux `flock`. The workflow also uses GNU `du` for capacity admission. These are existing deployment prerequisites. Git verifies the exact clean source revisions; the container engine verifies and controls the selected runtime; sudo preserves mixed database ownership; GNU copy preserves filesystem metadata; flock serializes host operations without leaking its lock descriptor into containers. Node filesystem copying cannot preserve all required ownership and extended metadata. Missing tools or failed commands stop the operation with a nonzero status. Install or update them through the deployment host's existing operating-system package process, then rerun admission checks before mutation.

The host distribution supplies these tools and their license notices; this repository does not vendor or redistribute them. Git, GNU coreutils and sudo retain their upstream licenses, and util-linux has component-specific licenses. Exact distribution package revisions and bundled license-file paths belong in each deployment's host inventory and are not pinned by these scripts. Container engine versions and immutable Box images remain governed by Ploinky's runtime checks. No new global installation is authorized by this document.

Existing component dependencies are documented in [OnlyOffice's dependency record](onlyOffice/dependencies.md) and [the smoke-suite dependency record](tests/smoke/dependencies.md). Soul uses SQLite's standard backup and transaction implementation rather than a custom database or WAL parser. Remove these optional recovery dependencies only when the corresponding preservation requirement is replaced and verified.

## UserPersisto Google client

The reviewed Google sign-in implementation authorizes promotion of the existing exact `openid-client` 6.8.7 pin from development to runtime dependencies. Node.js >=22 is the runtime prerequisite and supplies ESM, Web Crypto and fetch; it is not a third-party npm dependency. Google federation reuses the already selected `oidc-provider` 9.12.0 and adds no browser SDK, framework, global tool, transpiler or bundler to UserPersisto.

| Dependency | Purpose, scope and resolution |
| --- | --- |
| `openid-client` 6.8.7 | Required runtime server-side Google discovery, confidential authorization-code exchange, PKCE, response checks and explicitly enabled signature checks. Exact package/integrity recorded in `userPersistoAgent/package-lock.json`; install through the existing Ploinky agent dependency preparation. |
| `oauth4webapi` 3.8.7 | Runtime transitive dependency of openid-client for OAuth/OIDC protocol processing; locked exact resolved package and integrity. No further npm dependencies. |
| `jose` 6.2.10 | Runtime transitive dependency shared with the retained provider, for JOSE/JWK verification using Web Crypto; locked exact package and integrity. No further npm dependencies. |

The security-sensitive discovery, token-response validation, issuer metadata and JWKS/signature behavior justify retaining the specialized client over native fetch plus a homemade OIDC implementation. The installed package was already used by independent OIDC tests. Reusing the server library is smaller and better aligned with the existing provider than adding Passport, Express, Firebase or Google browser scripts. Moving the client to production ensures `npm ci --omit=dev` includes the verifier and its dependencies.

The sign-in button also serves a local copy of Google's approved icon PNG and Google Sans Medium font. Their origin, branding terms and included font license are recorded in `userPersistoAgent/public/auth/google-branding.md`. No third-party asset request is made from the sign-in page.

Upstream/update sources are [openid-client](https://github.com/panva/openid-client/tree/v6.8.7), [oauth4webapi](https://github.com/panva/oauth4webapi/tree/v3.8.7), and [jose](https://github.com/panva/jose/tree/v6.2.10). All exact installed revisions declare the MIT license; their `LICENSE.md` files under the resolved `node_modules/<package>/` retain Filip Skokan copyright notices (2016, 2022 and 2018 respectively). Include those copyright and permission notices when redistributing substantial package copies. There are no local upstream modifications or vendored copies. Package installation retains licenses; the repository stores lockfile integrity instead of an undeclared external checkout.

To update, review the upstream release and protocol changes, deliberately change the exact direct pin and regenerate the agent lockfile using npm, inspect resolved transitive versions/licenses, run production dependency preparation and the full UserPersisto protocol/security/browser matrix, then update this record. Do not upgrade the provider or image incidentally. The existing Ploinky preparation installs dependencies before runtime startup; unresolved modules fail startup instead of acknowledging authentication, and Google discovery/configuration errors fail closed while missing optional Google configuration leaves existing non-Google login usable. No global installation is required. Removing openid-client/oauth4webapi requires retiring Google sign-in and replacing the existing independent OIDC client tests or selecting another reviewed protocol implementation; jose remains required by oidc-provider even if Google is removed.
