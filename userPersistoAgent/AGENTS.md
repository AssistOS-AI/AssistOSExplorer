# userPersistoAgent Agent Guide

## Scope

userPersistoAgent is the authority for users, roles, capabilities, auth strategies, credits, subscriptions, Stripe billing, and audit. It uses embedded Persisto as its durable store and acts as the workspace SSO provider (`ssoProvider: true` in `manifest.json`).

## Mandatory Reading Order

1. Read `../AGENTS.md` for workspace-wide rules, coding style, module structure, and test-organization rules.
2. Read `manifest.json` for the container, SSO flag, `routerAccess.httpRoutes`, volumes, `enable` list, and env profiles.
3. Read `mcp-config.json` and `tools/registry.mjs` before changing any tool contract.
4. Read the matching `tests/*.test.mjs` file before changing `lib/`, `service/`, `runtime/`, or `tools/` behavior.
5. This checkout has no `docs/` tree and no `README.md`, so there are no local DS specs or HTML docs to consult. Do not invent spec references.

## Repository Rules

- Keep each route's access level in `manifest.json` (`authenticated`, `guest`, `public`) consistent with the handlers in `service/`; change both together.
- Secrets (`USERPERSISTO_SETTINGS_KEY`, `USERPERSISTO_RUNTIME_SECRET`) are generated by Ploinky; never hard-code or log them.
- Do not edit `external/Persisto/` or `vendor/` as part of agent changes; `external/Persisto/upstream.json` tracks the upstream source.
- All documentation and code comments must be written in English.
- Never add AI/coding-agent attribution to commits, release notes, changelogs, generated metadata, comments, or documentation.
- `AGENTS.md` is this agent's single instruction file for every coding agent; do not add a `CLAUDE.md`.

## Runtime Defaults

Uses `docker.io/assistos/ploinky-node@sha256:accd925fcbf460c1f4c7a5cd9e2d46539c615bbfad2e896cabb7556d8050a669`. The manifest sets `agent` to `exec sh /code/scripts/start.sh`, which creates `PERSISTENCE_FOLDER` (default `/data/persisto`) and runs `node main.mjs`. Readiness protocol is `mcp`. The `.data/userPersistoAgent` host folder is mounted at `/data`. The manifest enables `emailAgent`. The HTTP service port defaults to `7000` (`USERPERSISTO_SERVICE_PORT`).

## Key Paths

- `manifest.json`
- `mcp-config.json`
- `main.mjs`
- `lib/` (store, users, roles, credits, billing, audit, auth, oidc)
- `service/` (dashboard, auth, OIDC, password reset, SSO wizard, Google auth)
- `runtime/index.mjs`
- `tools/`
- `IDE-plugins/userpersisto-settings/` (the "My Account" settings plugin)
- `tests/` (`tests/helpers/`, `tests/browser/README.md`)

## Validation

Run the narrowest relevant test file after edits, then broaden when touching shared behavior:

- `node --test tests/<name>.test.mjs`
- `npm test` (runs `node --test tests/*.test.mjs`)

Some tests need a Ploinky-started environment (`PLOINKY_AGENTLIB_DIR`) or the sibling `../../ploinky` checkout; report such environment failures instead of weakening assertions. Browser flows live in `tests/browser/` and are described in its `README.md`.
