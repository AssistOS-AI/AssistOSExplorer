Documentation / Architecture

Architecture

The OnlyOffice integration separates authenticated Explorer session control, public editor transport, internal DocumentServer services, and the storage authority selected for each document.

Runtime And Trust Boundaries

Control And Editor Boundaries

The control service on target 7000 authenticates Explorer requests, resolves workspace or Confidential storage, creates session state, and signs short-lived editor configuration material. The public editor transport on target 8080 accepts only the forwarding tuple installed by the Router and strips browser credentials before proxying.

DocumentServer Services

DocumentServer, PostgreSQL, RabbitMQ with the Erlang Port Mapper Daemon, and optional Redis remain internal support services of the pinned image. OnlyOffice starts them through the manifest entrypoint and verifies their listeners, files, and process ownership before declaring the runtime ready. Router targets do not create physical-host port publications.

The DocumentServer wrapper and its foreground helpers run in one dedicated process group. During controlled replacement, OnlyOffice stops new admission, force-saves every writable session whose source document DocumentServer requested, and waits for its durable callback. Issued but unused configurations do not enter that wait. Before signalling the process group, the agent sends PUT to http://[::1]:8000/internal/cluster/inactive while the proxy remains live and observes every upgraded editor socket close after DocumentServer's terminal shutdown notification. This includes read-only editors. Only then may residual HTTP connections and the process group stop.

Native delivery has a two-second ceiling within the same thirty-second application drain deadline. The agent cancels the outstanding native HTTP request after socket closure because that endpoint's response can wait at least thirty seconds. With no upgraded editors it skips that request. A request or delivery failure keeps callback storage and DocumentServer alive. The wrapper's additional notification uses the same exact IPv6-loopback endpoint and a separate two-second total timeout within Ploinky's clean-exit window.

Storage Ownership

Ordinary workspace paths use the configured workspace store. Confidential paths use a Router-minted dpuConfidential delegation. The agent passes that delegation to dpuAgent for authorized reads, writes, and listing and rejects a Confidential session without a valid delegation.

Agent-owned DocumentServer logs, data, and library state use .data/onlyOffice/log, .data/onlyOffice/data, and .data/onlyOffice/lib. Session metadata uses /root/state/onlyoffice-sessions-v5.json inside the persistent agent workdir. The v5 hard cut does not read, migrate, or delete retired OnlyOffice data under .ploinky.

Delegation bearers never enter persisted session state. After a recreate, fresh authenticated control can restore the in-memory bearer only for an unexpired, previously loaded session with the same user, canonical browser route, stable document identity, and permissions. Unused or mismatched sessions stay inactive.
