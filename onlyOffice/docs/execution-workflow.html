Documentation / Execution workflow

Execution Workflow

An authenticated Explorer request creates a bounded editor session; the public proxy then carries only validated editor traffic and signed callbacks for that session.

Session And Editor Flow

Startup Completion

The agent resolves its bundled DocumentServer wrapper from the module location and launches its absolute path directly with /bin/bash. Startup works from the isolated agent home or another working directory without changing that directory or using a login shell; spaces and shell characters in the source path remain literal. Explicit command overrides retain their /bin/bash -lc behavior.

The first DocService process can serve HTTP while the pinned vendor script is still generating fonts. That phase restarts DocService and the converter. The wrapper waits for successful font generation and static compression before recording completion, then enters its final log tail. Readiness requires that record to match the live wrapper's PID, kernel start time, boot ID and current startup nonce, together with a successful DocService health response and the existing JWT, nginx and listener ownership checks. Each start invalidates earlier completion; failed or changed bootstrap state keeps the agent unready.

Before services start, the wrapper validates the two pinned static-compression commands and changes their find execution mode so gzip failures propagate. Compression preserves the selected assets, font paths, options and original files, followed by the vendor's nginx configuration and reload steps. An unknown command shape or failed compression prevents readiness.

Session State

Session creation resolves the current immutable topology generation and stores an atomic, guarded 0600 state file under the persistent work directory. Each session receives its own document key and callback URL. The state records when DocumentServer requests the source document, distinguishing a loaded editor from an issued configuration that was never consumed. Configuration and callback tokens are short-lived, body-bound JSON Web Tokens. Delegation bearers remain memory-only.

Unavailable Confidential Documents

A Confidential path absent from the delegated user’s visible tree returns 404 document_not_found; content without read access returns 403 document_forbidden. Neither response exposes document identity or credentials, resolves an editor, or creates a session. Unexpected storage errors retain their server-error handling. Live control isolation tests authenticate without following redirects, and WebSocket probes preserve transport query parameters with bounded timeout and early-close failure.

Callbacks And Recovery

The callback storage service authenticates its own token before using claims, rejects malformed or duplicated forwarding fields, enforces body limits, and persists document changes through the selected workspace or delegated DPU store. Signed status 4 records a no-change close; signed status 1 clears previous closure and drain receipts for a new editing cycle. Both require the exact authenticated session and document key. Restart recovery drains loaded writable sessions, ignores unused control configurations and sessions closed by final-save or no-change callbacks, persists bearer-free session state, and reopens only after the replacement topology generation is ready. The first fresh authenticated Confidential control request may reauthorize an unexpired previously loaded session only when its user, browser authority, document identity, and permissions still match; all mismatches remain inactive.

After every loaded writable session has a durable callback acknowledgement, the agent asks the IPv6-loopback DocService at http://[::1]:8000/internal/cluster/inactive to send its terminal shutdown notification while the proxy remains live. Every upgraded editor socket, including read-only sessions, must close within two seconds and the original thirty-second application drain deadline. Socket closure acknowledges delivery. Only after durable save and native socket closure succeed does the agent persist a separate drain receipt for loaded sessions, so later restarts do not force-save retired keys. A force-save callback alone does not prove closure. The agent then cancels the native HTTP wait and tears down residual HTTP connections and the process group. It skips the request when no upgraded editors remain. A failed request or delivery deadline keeps callback storage and DocumentServer alive with admission stopped. Graceful disconnect prevents the old editor from retrying against a retired generation; the wrapper's later additional notification remains bounded to two seconds.
