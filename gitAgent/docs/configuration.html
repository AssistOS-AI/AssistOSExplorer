Manifest and Environment

gitAgent follows the Ploinky manifest model and uses explicit environment variables for filesystem scope, LLM provider access, and GitHub auth integration. Dependency installation is owned by ploinky, so the manifest stays focused on runtime entrypoints and environment.

Manifest

Main runtime configuration file: gitAgent/manifest.json.

{
  "agent": "sh /code/scripts/startAgent.sh",
  "container": "docker.io/assistos/ploinky-node@sha256:accd925fcbf460c1f4c7a5cd9e2d46539c615bbfad2e896cabb7556d8050a669",
  "lite-sandbox": true,
  "profiles": {
    "default": {
      "install": "host sandbox git check, container apk install"
    },
    "embedded": {}
  }
}

The agent bootstrap script resolves workspace root and loads ordinary environment variables from process env first, then from .ploinky/.secrets when needed. Generated-local Soul Gateway credentials and Router transport values are Ploinky-owned and arrive through the mounted, verified Router descriptor rather than manifest environment declarations. In host sandbox mode, startup verifies that git is available on the host; in container mode, the profile installs the container Git packages when needed. Node dependency installation is handled by ploinky before the agent command starts.

Core Environment Variables

Variable Usage
ASSISTOS_FS_ROOT, WORKSPACE_ROOT, PLOINKY_WORKSPACE_ROOT Define allowed filesystem roots for path validation in Git tools.
PLOINKY_GITHUB_CLIENT_ID, PLOINKY_GITHUB_CLIENT_SECRET, PLOINKY_GITHUB_SCOPE Enable GitHub device flow behavior for auth tools.
ASSISTOS_GIT_BINARY (optional) Overrides Git executable path detection in the Git service.

Auth State and Secrets

GitHub auth state is persisted only under user-scoped files in .data/gitAgent/github-auth/, while access tokens are stored through user-owned DPU secret keys derived from the routed Ploinky user. The GitHub auth tools declare a dpuGitSecrets MCP delegation in mcp-config.json; the router mints that short-lived grant only for signed-in users, and gitAgent forwards it to DPU as x-ploinky-user-delegation. DPU grants gitAgent only the read role allowed by permissions.manifest.json agent policy. Push and pull operations can read token metadata from request context or from stored auth state when token input is omitted.

Every local state operation revalidates the full managed directory chain, including the state and temporary files. Symbolic links are rejected with PLOINKY_AGENT_DATA_POLICY_VIOLATION; the agent does not follow or replace them and never reads or migrates a retired state location.
