MCP Tools

All Git operations are declared as Model Context Protocol (MCP) tools in gitAgent/mcp-config.json and executed through gitAgent/tools/git_tool.sh.

Tool Groups

Group Tools Purpose
Repository inspection git_info, git_status, git_diff, git_repos_overview, git_diagnose, git_check_large_files Read repository shape, branch/upstream state, diffs, and diagnostics.
Repository lifecycle git_init_repository, git_clone_repository, git_create_github_repository, git_submodule_add Create top-level repositories or explicitly add an existing remote as a staged Git submodule. Independent nested repositories are rejected.
Branch operations git_branch_list, git_branch_checkout, git_branch_create, git_branch_merge List local and remote branches, switch branches, create branches from an optional start point, and merge into the current branch.
GitHub repository discovery git_github_repository_targets, git_github_repositories List authenticated user or organization creation targets and repositories available through GitHub.
Index and working tree control git_stage, git_stage_exact, git_unstage, git_untrack, git_check_ignore, git_add_ignore, git_remove_ignore, git_restore Manage exact or incremental stage state, ignore rules, ignore checks, and restore operations.
Conflict handling git_conflict_versions, git_checkout_conflict, git_resolve_conflict Read conflict sides, apply ours/theirs selection, or request an LLM-assisted base/ours/theirs merge.
Stash and commit flow git_stash, git_stash_pop, git_stash_list, git_commit_message, git_commit Temporarily store changes, generate an LLM-assisted message from supplied diffs, and create commits.
Remote and identity git_remote_set, git_push, git_fetch, git_pull, git_identity, git_set_identity Add or update remote URLs, run remote synchronization, and manage author identity settings.
GitHub auth bridge git_auth_status, git_auth_begin, git_auth_poll, git_auth_disconnect, git_auth_store_token Manage GitHub token lifecycle used by push and pull operations.

Common Input Rules

Most tools require a path argument and reject values outside allowed workspace roots. Operations that target subsets use files arrays, remote operations can accept token overrides through token, and conflict checkout requires source constrained to {"ours","theirs"}.

git_submodule_add requires a parent path inside a Git worktree, a child directory name, and an existing remoteUrl with a checkoutable commit. It stages the resulting .gitmodules entry and gitlink without committing them.

git_fetch requires path and accepts an optional token. It refreshes only the named current branch's configured upstream reference, without changing working files, staging, or HEAD, recursing into submodules, or creating a remote repository. A branch without an upstream returns ok: true, skipped: true, reason: "no_upstream". Detached HEAD, unreachable remotes, and deleted source branches fail explicitly. After success, git_status with includeAhead: true reports updated ahead and behind counts. Fetch still writes Git metadata; it is not a read-only filesystem operation.

git_pull runs with --no-autostash. A client that needs to stash local work must obtain explicit permission and call git_stash separately; a configured Git autostash setting cannot bypass this boundary.

git_check_large_files requires path and operation (commit or push). Push inspection also accepts remote, branch, and setUpstream. It reads object sizes without fetching or modifying working files, staging, commits, or remotes. A file version of at least 52,428,800 bytes returns ok: false, code: "large_files_warning", with operation, thresholdBytes, and files entries containing oid, path, and sizeBytes.

git_commit and git_push enforce the same check before mutation, including before GitHub remote creation during push. Callers must show the warning and ask for permission. After approval, retry with approvedLargeFileOids containing the approved blob IDs. A different large blob requires another warning; no blanket approval flag exists. Commit inspection uses added or modified index versions. Push inspection includes earlier outgoing commits and compares against local references for the target remote, so stale references and matching refspecs may over-warn. The 50 MiB threshold is not a provider limit, and approval does not guarantee that the remote will accept the push.

Execution Characteristics

Each invocation starts a new Node process through the wrapper script. Git subprocesses run with timeout and error-normalization behavior, and failures are returned as explicit MCP JSON payloads with ok: false.
