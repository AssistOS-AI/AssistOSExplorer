Git terminology

Git agent

The Git agent performs repository inspection and mutation for the workspace selected by Explorer. Its Model Context Protocol tools cover repository creation, status, history, staging, commits, branches, remotes, ignore rules, and authenticated GitHub operations while keeping path resolution inside the configured workspace root.

Model Context Protocol

Model Context Protocol is the configured tool boundary used by the agent. Tool names and input schemas come from the local MCP configuration and execution remains subject to the agent's verified runtime authorization.

Ploinky

Ploinky starts the agent, supplies its runtime environment, and mediates authenticated invocation context. The agent does not treat client-declared identity as authorization.

Workspace root

The workspace root is the filesystem boundary supplied by Ploinky and used to resolve repository paths. Explorer paths are workspace-relative; the Git agent rejects paths that escape this boundary.

Secret delegation

Secret delegation lets the Git agent request an authorized GitHub credential from DPU without storing the plaintext credential in Git metadata or browser state. The secret-store client verifies the delegated response before an authenticated provider operation proceeds.
