Local instruction skills

The default robot selects the bundled copilot source and live workspace source. Current working files are captured when an external turn starts, after any task queue wait. Descriptor edits, helper edits, executable-mode changes and new repositories are visible on the next execution. Steering an active execution keeps its current revision.

Discovery scope

Ploinky carries the host launch directory into its existing workspace mount as PLOINKY_SKILL_SCOPE. A conversation saves that canonical scope separately from its native cwd. Discovery cannot retarget a saved scope through a symlink. No Box restart, new workspace mount or broader agent grant is required. Existing HTTP consumers retain their activation scope; a later CLI invocation receives its own launch scope. Direct local integrations without launch metadata use their explicitly configured workspace root.

Discovery checks .agents/skills and .claude/skills beneath the scope, and skills at the scope root or repository/package boundaries. It reads untracked and uncommitted files without Git. Ordinary descendant directories are traversed; hidden state, dependencies, build outputs and robot private data are excluded. Contained compatibility catalog symlinks are deduplicated. The source projection omits .git metadata and node_modules, matching import behavior; installed dependency trees are not captured resources. Included skill trees cannot contain symlinks, special files or nested descriptors.

Selection

/skills list shows inventory states and diagnostics. /skills use workspace,copilot selects sources; /skills use none explicitly selects nothing. A qualified workspace identity is relative to the saved scope, for example workspace:Repo/.agents/skills/review. Imported identities use documents/read-pdf. Use a qualified identity to resolve an ambiguous native name. Automatic workspace conflicts use only a unique nearest ancestor owner; unrelated candidates remain visibly conflicted. Filename ordering does not select a winner.

Settings reads and changes the same policy. Without a conversation context it edits scoped robot defaults for future conversations; a session-qualified view uses the conversation's saved cwd and policy. Inventory, next-execution selection and an active revision are distinct. Mutations require the displayed policy version. A toggle disables one source identity; /skills deny-name review blocks that logical name across sources and /skills allow-name review removes that block. Old name exclusions are retained. Enabling a conflict row explicitly chooses its identity.

A rejected toggle leaves the saved selection and version unchanged. To switch between two explicitly chosen skills with the same name, disable the previous choice before enabling its replacement. A disabled individual skill may be edited into an invalid state or removed without blocking the conversation; it stays disabled if its files return. Re-enabling it validates its current files and source.

Name exclusions remember the native names of valid workspace skills when you change selection or migrate an older policy. This keeps an excluded skill disabled if its descriptor later disappears or becomes invalid, even when its folder has a different name. A valid renamed skill uses its new name. /skills allow-name removes the remembered exclusion. An older missing skill whose native name cannot be proven still reports an error.

Local imports also retain verified names for their skill directories when selection changes. A disabled imported skill stays disabled through temporary invalid edits, including when it was added after the source was registered. Valid renames update that record; replacing the registered source does not reuse another generation's record. Invalid folders with no proven identity still report an error when their source is required.

Open the WebChat menu and choose Conversation skills to edit the current conversation in Explorer. This action carries the robot and saved session identity, so browsing another folder does not change the conversation's scope. Invalid or incomplete links show an error. Ordinary Explorer Settings still edits defaults for future conversations.

/skills override remote-set workspace:Repo/.agents/skills declares a local replacement for a HTTPS source and selects that local catalog. The remote source stays suppressed when the local files disappear, so deletion cannot silently restore old distribution bytes. Required missing or invalid sources fail visibly; unrelated malformed automatic candidates are excluded with diagnostics.

Execution and continuation

A task references one canonical conversation policy. The execution wrapper captures complete selected trees, checks content and executable modes, rechecks membership and policy version, and publishes a content-addressed catalog. Unstable inputs receive bounded retries then an explicit failure. Empty selections still send an authoritative empty catalog to ALA. Native home, cwd, backend and conversation history remain unchanged by refresh.

/skills pin keeps the last executed catalog, including an empty catalog. /skills live returns to live capture. Pinned selection cannot be toggled until live mode is restored. Local imports read original source files; HTTPS imports retain the registered generation until explicitly reimported and reselected. Removing or replacing a selected registered source requires reselection instead of falling back to its old execution copy.

Migration and retention

Existing explicit empty selections stay empty. Historical default copilot-only records cannot distinguish an implicit default from an explicit bundled-only choice; they add workspace with a diagnostic and /skills use copilot opt-out. Historical imported selections lack source/generation provenance and require explicit reselection unless such provenance can be proved. Their intact old catalog remains available only through explicit pinning. A resumed terminal task never overwrites a later conversation policy.

Preparing and active execution leases, explicit pins, legacy recovery catalogs and each conversation's latest two revisions are retained. Collection retires up to ten unreferenced content revisions older than an hour after an execution, retaining at least two per robot; legacy UUID catalogs remain. Reserved abandoned preparation is collected only after proving its process owner dead. Pins and many retained conversations can use substantial disk space; this is retention, not a fixed disk quota.

This feature serves RoboTeam Anthropic SKILL.md instruction skills. Typed AgentLib module reload and dependency-package snapshots are separate capabilities. ALA controls native task-skill registration; selection does not revoke ordinary file access already authorized by the execution workspace or home.
