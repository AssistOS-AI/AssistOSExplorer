Local instruction skills

Status: workspace skill discovery is disabled. RoboTeam does not scan the workspace, its projects, package folders or local checkouts for skills. Skill sources are the bundled catalog and repositories registered on a robot, resolved through the Ploinky marketplace endpoint. The workspace selection and discovery rules below are retained for registered local sources and for historical policies only.

The front copilot selects the bundled copilot skillset and the individual launch-workflow skill. RoboTeam resolves registered repositories and installs symlinks through Ploinky before execution. Descriptor and helper edits are immediately visible through existing links. New skill membership is resolved at the next execution.

Discovery scope

RoboTeam does not scan the workspace for skill catalogs. There is no workspace launch scope and no PLOINKY_SKILL_SCOPE-based discovery. Registered repositories keep their canonical source; remote and managed sources resolve through the Ploinky marketplace endpoint, and local sources are limited to explicitly registered robot repositories.

Selection

Explorer Conversation skills shows the inventory and changes the selection. The CLI loads the configured selection automatically and has no skill-administration commands. Imported identities use documents/read-pdf. Use a qualified identity to resolve an ambiguous native name. Filename ordering does not select a winner.

Settings reads and changes the same policy. Without a conversation context it edits scoped robot defaults for future conversations; a session-qualified view uses the conversation's saved cwd and policy. Inventory, next-execution selection and an active revision are distinct. Mutations require the displayed policy version. A toggle disables one source identity; existing logical-name exclusions remain in the policy. Old name exclusions are retained. Enabling a conflict row explicitly chooses its identity.

A rejected toggle leaves the saved selection and version unchanged. To switch between two explicitly chosen skills with the same name, disable the previous choice before enabling its replacement. A disabled individual skill may be edited into an invalid state or removed without blocking the conversation; it stays disabled if its files return. Re-enabling it validates its current files and source.

Name exclusions remember the native names of valid workspace skills when you change selection or migrate an older policy. This keeps an excluded skill disabled if its descriptor later disappears or becomes invalid, even when its folder has a different name. A valid renamed skill uses its new name. An older missing skill whose native name cannot be proven still reports an error.

Local imports also retain verified names for their skill directories when selection changes. A disabled imported skill stays disabled through temporary invalid edits, including when it was added after the source was registered. Valid renames update that record; replacing the registered source does not reuse another generation's record. Invalid folders with no proven identity still report an error when their source is required.

Open the WebChat menu and choose Conversation skills to edit the current conversation in Explorer. This action carries the robot and saved session identity, so browsing another folder does not change the conversation's scope. Invalid or incomplete links show an error. Ordinary Explorer Settings still edits defaults for future conversations.

An existing policy may declare a local replacement for a HTTPS source and select that local catalog. The remote source stays suppressed when the local files disappear, so deletion cannot silently restore old distribution bytes. Required missing or invalid sources fail visibly; unrelated malformed automatic candidates are excluded with diagnostics.

Execution and continuation

A task references a conversation policy. RoboTeam installs live links and records the selected entries, policy version and installation revision. ALA receives the containing workspace read-only and the working folder writable at identical canonical paths using --cwd and --folder. ALA performs no task-skill discovery or directory preparation. RoboTeam adds the initial skills instruction once per native conversation.

Pinned catalogs remain historical recovery evidence but cannot run in live installation mode. Restore live selection before execution. Local and HTTPS sources resolve through Ploinky’s current workspace-first repository view. Missing required sources fail rather than falling back to old copies.

Migration and retention

Existing explicit empty selections stay empty. Historical default copilot-only records cannot distinguish an implicit default from an explicit bundled-only choice; they add workspace with a diagnostic; selection can be adjusted in Explorer. Historical imported selections lack source/generation provenance and require explicit reselection unless such provenance can be proved. Their intact old catalog remains available only through explicit pinning. A resumed terminal task never overwrites a later conversation policy.

Preparing and active execution leases, explicit pins, legacy recovery catalogs and each conversation's latest two revisions are retained. Collection retires up to ten unreferenced content revisions older than an hour after an execution, retaining at least two per robot; legacy UUID catalogs remain. Reserved abandoned preparation is collected only after proving its process owner dead. Pins and many retained conversations can use substantial disk space; this is retention, not a fixed disk quota.

This feature serves RoboTeam Anthropic SKILL.md instruction skills. Typed AgentLib modules are separate. RoboTeam controls installed skill links; selection does not revoke ordinary read access to the larger workspace.
