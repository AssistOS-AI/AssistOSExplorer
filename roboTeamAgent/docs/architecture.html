Documentation / Architecture

Architecture

The rootless Ploinky Box starts RoboTeam with the bounded nested-Podman contract; Podman 6 inside it starts one Chromium or Webtop container per active robot.

Outer runtime

The custom roboteam-runtime-v3 image derives from an immutable Podman 6 upstream index and includes Node.js, npm, fuse-overlayfs, pasta, curl, and Git. Inner storage lives at /data/podman/storage. The manifest pins docker.io/assistos/roboteam-agent@sha256:e8282f4ccd23ac4520421daecf46f208225b45b34bb9e40a9937e2c40821215d, published from image-definition commit b0490170a976b67504d3bfb0bdbe09e3df7dcdde with v3 runtime contracts for amd64 and arm64, and requests Ploinky's nestedPodman capability. The install hook verifies the runtime contract before startup. Image updates must preserve this contract on both architectures.

Robot runtime

RobotStore owns durable metadata and directories. RuntimeManager constructs exact Podman argument vectors, tracks active runs in memory, and removes only labelled RoboTeam containers. The HTTP server authenticates ownership and reverse-proxies Selkies HTTP and WebSocket traffic.

Networking

The outer container stays on Ploinky's managed network. AgentServer/MCP uses port 7000 and the authenticated RoboTeam UI uses port 3001. Inner containers use pasta; Selkies port 3000 is published only to a random outer loopback port. The proxy preserves the configured Ploinky subfolder.
