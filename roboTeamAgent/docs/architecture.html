Documentation / Architecture

Architecture

The rootless Ploinky Box starts RoboTeam with the bounded nested-Podman contract; Podman 6 inside it starts one Chromium or Webtop container per active robot.

Outer runtime

The custom roboteam-runtime-v4 image provides Podman 6, Node.js, npm, Bubblewrap, fuse-overlayfs, pasta, curl, and Git. Inner storage lives at /data/podman/storage. The manifest follows the AssistOS-managed runtime channel and requests Ploinky's nestedPodman capability; the install hook verifies the runtime contract before startup.

Robot runtime

RobotStore owns workspace-wide durable metadata and directories. RuntimeManager constructs exact Podman argument vectors, gives each robot one active ALA slot and a FIFO queue, tracks active runs in memory, and removes only labelled RoboTeam containers. It retains at most one GUI container per robot. It reuses that container when mode and resolved cwd match, or replaces it after the active task finishes when a queued graphical task requires another mode or cwd. Cancelling a native graphical task for human takeover creates a manual-control hold that blocks the queue without stopping the container. The explicit MCP stop tools stop ALA without creating that hold. A validated continuation resumes the exact interrupted request ahead of waiting work and releases the hold. Inner runs use --ipc=none so bounded nested Podman does not attempt a forbidden mqueue mount; GUI containers receive a private /dev/shm tmpfs. When the cached Codex runtime is added to a GUI container, the constructed PATH retains LinuxServer's /lsiopy/bin so the Selkies backend remains executable. The HTTP server enforces administrator-only creation and deletion and reverse-proxies authenticated Selkies HTTP and WebSocket traffic.

Networking and task execution

The outer container stays on Ploinky's managed network and is enabled globally so it can invoke the current /workspace/AdvancedLanguageAgent/bin/ala.mjs checkout. AgentServer/MCP uses port 7000 and the authenticated RoboTeam UI uses port 3001. Inner containers use pasta; Selkies port 3000 and MCP port 8100 are published only to random outer loopback ports. Desktop uses a Streamable HTTP bridge to computer-use-linux; browser uses Playwright MCP over CDP to the visible Chromium. ALA runs separately in the outer runtime with the robot home and caller cwd, and starts Codex inside its Bubblewrap sandbox. Each start MCP command remains alive until its queued RoboTeam task and ALA process finish. The command writes parsed ALA messages to standard error for Ploinky task logs and writes only the final result to standard output. A cancelled GUI command stops its exact inner task and returns an opaque native continuation handle. resumeTaskForRobot receives that handle through the Router and starts the replacement command on the same caller-owned task timeline. The real entrypoint prevents Ploinky's Node.js symlink-preservation flags from changing the base of ALA's relative ESM imports. Failed ALA tasks expose a bounded diagnostic tail through internal task status.

Nested Bubblewrap limitation

ALA normally creates a user namespace together with private PID, IPC, and UTS namespaces and a private procfs. In the current nestedPodman deployment, the kernel rejects the private procfs mount inside that additional user namespace. ALA detects this condition before execution and uses the outer container's admitted mount capability only to construct the private PID namespace and procfs, omitting the extra user namespace and dropping all capabilities before Codex starts. The Bubblewrap filesystem boundary, controlled writable mounts, filtered environment, isolated temporary directory, and private procfs remain in force. Codex does not create a second native sandbox inside this boundary. Failure of both private-proc construction paths stops the task rather than starting Codex without ALA isolation.

Runtime tool cache

ToolCache resolves current Codex, computer-use-linux, Supergateway, and Playwright MCP releases when needed. It installs candidates into unique generations under /data/tool-cache, probes them, and switches current.json atomically. GUI containers mount exact tool generations read-only; ALA receives the cached Codex binary on PATH. An unavailable upstream falls back only to the last validated generation.
