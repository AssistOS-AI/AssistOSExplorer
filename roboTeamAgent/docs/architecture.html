Documentation / Architecture

Architecture

The rootless Ploinky Box starts RoboTeam with the bounded nested-Podman contract; Podman 6 inside it starts one Chromium or Webtop container per active robot.

Outer runtime

The custom roboteam-runtime-v4 image provides Podman 6, Node.js, npm, Bubblewrap, fuse-overlayfs, pasta, curl, and Git. Inner storage lives at /data/podman/storage. The manifest follows the AssistOS-managed runtime channel and requests Ploinky's nestedPodman capability; the install hook verifies the runtime contract before startup.

Robot runtime

RobotStore owns durable metadata and directories. RuntimeManager constructs exact Podman argument vectors, tracks active runs in memory, and removes only labelled RoboTeam containers. The HTTP server authenticates ownership and reverse-proxies Selkies HTTP and WebSocket traffic.

Networking and task execution

The outer container stays on Ploinky's managed network. AgentServer/MCP uses port 7000 and the authenticated RoboTeam UI uses port 3001. Inner containers use pasta; Selkies port 3000 and MCP port 8100 are published only to random outer loopback ports. Desktop uses a Streamable HTTP bridge to computer-use-linux; browser uses Playwright MCP over CDP to the visible Chromium. ALA runs separately in the outer runtime with the robot home and caller cwd.

Runtime tool cache

ToolCache resolves current Codex, computer-use-linux, Supergateway, and Playwright MCP releases when needed. It installs candidates into unique generations under /data/tool-cache, probes them, and switches current.json atomically. GUI containers mount exact tool generations read-only; ALA receives the cached Codex binary on PATH. An unavailable upstream falls back only to the last validated generation.
