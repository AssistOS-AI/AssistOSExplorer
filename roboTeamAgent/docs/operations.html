RoboTeam Documentation

RoboTeam exposes robot management and task execution as MCP tools. The Ploinky Router applies the tool policy before RoboTeam receives a call.

MCP tools

ToolWhat it does
robot_createCreates a persistent workspace robot with a workspace-unique name and optional specialization. Only an authenticated administrator may call it.
robot_listReturns every robot in the workspace, including its specialization and current run state. This is an internal workspace-agent tool.
robot_deleteDeletes a stopped robot and its persistent home. Only an authenticated administrator may call it.
openDesktopForRobotStarts or reuses a Desktop without ALA. Use it to log in to Codex or configure the robot's persistent home.

stopDesktopTaskForRobotStops the active Desktop ALA task but leaves the Desktop container and visible session running.
startBrowserTaskForRobotQueues a native asynchronous Ploinky task. It starts or reuses a Browser, runs ALA with the Playwright MCP bridge, streams ALA messages, and completes when ALA exits.
stopBrowserTaskForRobotStops the active Browser ALA task but leaves the Browser container and visible session running.
startSimpleALATaskForRobotQueues a native asynchronous Ploinky task and runs ALA without starting or replacing a GUI container.
stopSimpleALATaskForRobotStops the active non-GUI ALA task.

How RoboTeam runs ALA

ALA is the LLM execution process. RoboTeam starts it in the outer RoboTeam container, in parallel with the graphical container. ALA then starts the selected coding-agent CLI inside its Bubblewrap sandbox. The Desktop and Browser MCP servers stay inside their graphical containers and are reachable by ALA through random loopback ports.

The concrete paths and random port differ for each robot and task. A Desktop task produces an invocation equivalent to:

ala \
  --home /data/robots/<robot-id>/home \
  --cwd /workspace/<project> \
  --taskFile /data/robots/<robot-id>/runtime/<task-id>.prompt \
  --ca codex \
  --MCPServers desktop=http://127.0.0.1:<port>/mcp

A Browser task uses the same command shape with browser=http://127.0.0.1:<port>/mcp. A Simple task omits --MCPServers and does not start a graphical container.

ALA argumentMeaning in RoboTeam
--homeThe robot's persistent home. ALA uses it for coding-agent authentication and configuration. The same directory appears as /config in the graphical container.
--cwdThe caller-selected workspace directory. ALA uses it as the writable work tree. Desktop and Browser containers receive the same directory at /workspace.
--taskFileA private file written by RoboTeam with the task prompt. RoboTeam uses a file so long prompts do not need to be embedded in the process argument list.
--caSelects codex, opencode, pi, or auto. The selected CLI must exist and its account state must be available through --home.
--MCPServersSupplies the task-local Desktop or Browser Streamable HTTP MCP address. The current ALA adapter injects this URL into Codex configuration for the run.
--skillSetsOptional comma-separated skill names exposed from <cwd>/.agents/skills.
--modelOptional native model override for the selected coding agent.

--home supplies saved state; it does not install a coding-agent executable. RoboTeam prepares the current Codex package in its shared tool cache and places it on ALA's PATH. OpenCode and Pi are supported by ALA but must already be provisioned in the outer runtime before RoboTeam can select them. Use Codex for Desktop and Browser automation because task-local MCP URL injection is currently implemented only by the Codex adapter. OpenCode and Pi can run Simple tasks once provisioned.

Task and container lifetime

The three start tools use Ploinky's native asynchronous task contract. Their initial MCP response contains the Ploinky task id. Standard error becomes the live task log, standard output becomes the final result, and the worker process remains alive until ALA exits. Callers use the normal Ploinky /task status route for completion and getSessionUrlForRobotDesktop or getSessionUrlForRobotBrowser for the live GUI URL.

Each robot has one active ALA slot and a FIFO queue shared by Desktop, Browser, and Simple tasks. A new request waits instead of failing because another task is active. A completed or stopped GUI task leaves at most one container running. RoboTeam reuses it when the next graphical task has the same mode and resolved cwd. A different mode or cwd replaces the idle container before the queued task starts. A Simple task leaves an existing GUI container untouched. Use the separate container-stop tool when the visible session is no longer needed.

RoboTeam starts ALA with ALA_EVENT_STREAM=1. It converts coding-agent-message events into readable progress text, keeps the final ALA standard output separate, and lets Ploinky retain the complete forwarded task log. State changes such as queued, starting, and running also appear in that log.

AchillesCLI calls

AchillesCLI's list-robots C-Skill calls robot_list through the Ploinky Router. Its launch-robot C-Skill accepts desktop <robot name>: <task> or browser <robot name>: <task>. It passes the current AchillesCLI workspace as cwd and calls the matching start tool with callToolWithoutWait. The background-task observer polls the native Ploinky task, persists new log text, and reports completion or failure. The launcher polls only the matching session-URL tool until the GUI is ready, then returns the Selkies link while observation continues.

First-use preparation

The first operation that needs Codex or a GUI automation server resolves the current release, installs it into /data/tool-cache, and validates it. Later starts reuse the active generation. When release lookup fails, RoboTeam uses the last valid generation if one exists.

Nested sandbox diagnostics

The current RoboTeam container cannot mount ALA's private procfs inside an additional user namespace. ALA therefore uses its capability-assisted private-proc path, retains its other Bubblewrap boundaries, and drops all capabilities before Codex starts. An error stating that neither private-proc path is available indicates a runtime capability or seccomp regression. RoboTeam must not bypass ALA or start Codex unsandboxed.
