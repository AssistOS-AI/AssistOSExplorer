Operations

Robot management

robot_create, robot_list, and robot_delete manage workspace-scoped robots by globally unique name. Creation and deletion require an authenticated administrator; internal workspace agents may list and run robots. openDesktopForRobot starts a manual desktop for configuring the persistent coding-agent home.

Task tools

ModeStart / stop
DesktopstartDesktopTaskForRobot / stopDesktopTaskForRobot
BrowserstartBrowserTaskForRobot / stopBrowserTaskForRobot
Simple ALAstartSimpleALATaskForRobot / stopSimpleALATaskForRobot

Every start operation returns a taskId. Desktop and Browser starts also return the deterministic authenticated sessionUrl. Callers poll getTaskStatusForRobot and present that URL after the task reaches running, which follows Selkies and MCP readiness. A retained GUI container is reused only when mode and resolved cwd match; if the same-mode container is idle but mounted on another cwd, RoboTeam removes and recreates it with the new /workspace mount. GUI task stop preserves the container; use stopDesktopContainerForRobot or stopBrowserContainerForRobot for removal.

First-use preparation

The first operation that needs Codex or a GUI automation server resolves the current release, installs it into /data/tool-cache, and validates it. Later starts reuse the active generation. When release lookup fails, RoboTeam uses the last valid generation if one exists.

Live work

The start response and getSessionUrlForRobotDesktop or getSessionUrlForRobotBrowser expose the same Router-relative Selkies URL. A user opening it watches the exact display controlled by ALA through the container's automation MCP bridge.

Nested sandbox diagnostics

The current RoboTeam container cannot mount ALA's private procfs inside an additional user namespace. This is expected to select ALA's capability-assisted private-proc path, which retains the Bubblewrap filesystem, process, temporary-directory, and environment boundaries and drops all capabilities before Codex starts. An error stating that neither private-proc path is available indicates a runtime capability or seccomp regression; RoboTeam must not bypass ALA or start Codex unsandboxed.
