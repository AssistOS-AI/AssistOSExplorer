Profiles & Desktops

An authenticated user creates a robot profile, starts its desktop, interacts with Chromium and the terminal through noVNC, and stops the desktop without deleting its state.

Create and inspect profiles

In AchillesIDE Explorer, select RoboTeam in the file-explorer toolbar immediately after WebMeet. The runtime plugin opens the profile dashboard through the authenticated agent-port base path declared in manifest.json. On narrow screens Explorer places the same action in its Tools menu.

The create form accepts a name and optional specialization. RoboTeam assigns an opaque profile identifier, the authenticated Ploinky user as profile owner, a stable numeric UID, and six persistent directories.

DirectoryUse
home/Desktop user configuration and command-line application state.
workspace/Private working files; xterm opens in this directory.
browser/Chromium user data, cookies, local storage, and session state.
downloads/Profile-owned downloaded files.
logs/Desktop process output used for diagnostics.
runtime/Short-lived XDG runtime files for the active desktop.

Profile metadata is descriptive. The specialization field does not select skills or start tasks.

Desktop lifecycle

Selecting Open desktop allocates a display slot and starts Xvfb, Openbox, xterm, Chromium, x11vnc, and websockify with the profile UID and profile-specific environment. The browser then opens `desktop.html`, loads noVNC, and connects to the authenticated WebSocket route. Selecting Stop desktop terminates the processes in reverse dependency order.

One RoboTeam instance accepts at most `ROBOTEAM_MAX_ACTIVE_DESKTOPS` concurrent sessions. A stopped profile consumes persistent disk but no desktop process slot.

MCP operations

ToolObservable result
robot_profile_createCreates a profile owned by the authenticated user and returns its metadata and desktop URL.
robot_profile_listReturns only profiles owned by the authenticated user.
robot_desktop_startStarts or reuses the named profile desktop and returns the browser-accessible URL.
robot_desktop_stopStops the active session and preserves the profile directories.

MCP commands receive the authenticated user metadata from Ploinky's AgentServer and call the loopback RoboTeam service with a generated internal token. The browser UI uses Ploinky's browser mutation proof for state-changing requests.
