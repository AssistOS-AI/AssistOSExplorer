# Smoke test dependencies

The composed Copilot live-skills gate and the Codex-authenticated Copilot gate add no packages or global installations; route A of the Codex gate adds none either. It uses Node.js built-ins and the smoke suite's existing dependencies. Node.js is a runtime prerequisite; use the repository-supported Node.js 20+ environment and the Node version in the verified deployed image for runtime observations.

| Dependency | Purpose and resolution | License and maintenance |
| --- | --- | --- |
| `@playwright/test` 1.60.0 | Existing required development dependency in `package.json` and `package-lock.json`, with its locked `playwright` and `playwright-core` transitive packages. Drives real browser input and assertions; built-in HTTP checks cannot replace this browser behavior. | Apache-2.0. License and notices remain in installed package directories. Source/update: https://github.com/microsoft/playwright. Follow the existing `npm ci` and `npm run install:browsers` setup; update the lockfile and browser together through normal suite validation. |
| Playwright Chromium | Existing required browser for the selected Chromium project, resolved by the pinned Playwright installation. Its revision and platform downloads are specified by the locked `playwright-core` browser manifest. | Chromium's BSD-style and bundled third-party license notices ship with the browser distribution. Source: https://chromium.googlesource.com/chromium/src/. No browser binaries are vendored here. A missing browser fails Playwright startup; install with the existing documented command. |
| Podman | Existing required deployment/observation CLI for the selected Ploinky Box, available on the selected host and inside the exact verified Box image. Runtime and transitive system dependencies are those in that immutable image and the supported host Podman installation; the gate adds none. Reads exact container metadata and executes bounded read-only Node observers. The Codex-authenticated Copilot gate also runs bounded Node write programs through `podman exec -i`: they create, read back and remove one run-owned credential file in a test robot, always with the credential on stdin. | Apache-2.0. Source/update: https://github.com/containers/podman. Preserve installed distribution notices. Use the repository deployment prerequisites; the gate does not install or update Podman. Missing Podman, incompatible inspect output or a mismatched host fails before fixture creation. |
| Deployed RoboTeam tool-cache `@openai/codex` client | Runtime prerequisite of the Codex-authenticated Copilot gate. RoboTeam resolves `@latest` into its own tool cache, and the gate only observes the package name, version and generation through a read-only program. It installs and pins nothing, and `CODEX_TEST_EXPECT_CODEX_VERSION` optionally pins the expected version. Route A runs only on an allowlisted build (version, platform, native SHA-256). | Apache-2.0. Source: https://github.com/openai/codex. Preserve the notices shipped in the installed package. A missing client fails with exit 20 (`codex-client-missing`). |
| Operator's seed-only Codex CLI (route B only) | Used by a person, once per seed or reseed, for `codex login --device-auth` into an isolated `HOME` and `CODEX_HOME` under the gate's private root. The gate prints the command and never executes the binary. It is named by `CODEX_TEST_AUTH_SEED_BIN`, which has no default. | Apache-2.0. Source: https://github.com/openai/codex. No copy of any other Codex login is used. |
| The owned Codex login stream (route B only) | A credential prerequisite, not a package: one ChatGPT login cache under `CODEX_TEST_AUTH_ROOT` (directories 0700, files 0600), seeded once from a separate login and serialized by a host lock. It holds no API key. Retired streams keep a credential at rest until the operator deletes them. | Not software; it carries no license. Reseed with `retire` and a new login. A missing or unsafe stream fails before any browser or Box step (exit 10 or 14). |
| The owner's Codex login (route A) | A credential prerequisite, not a package: the machine owner's existing ChatGPT login at `$HOME/.codex/auth.json`, read read-only and never copied whole. Only the access token, the account id and `last_refresh` are used, and the refresh token never leaves the owner file. The owner keeps it current. | Not software; it carries no license. A missing, unsafe, invalid or near-expiry login fails before any browser or Box step (exit 10 or 14). |
| Codex client qualification harness and allowlist (route A) | `scripts/codex-client-qualify.mjs` runs a copied client against a loopback mock with fabricated tokens, is never a gate and never contacts a provider. The allowlist in `lib/codex-client-qualification.mjs` is committed code and changes only through reviewed commits. | Uses Node.js built-ins only; the copied client keeps its own Apache-2.0 license and notices (https://github.com/openai/codex). An unqualified build fails with exit 20 (`client-unqualified`). |
| Bounded Podman write programs | The credential programs of the Codex-authenticated gate run in the exact RoboTeam container through `podman exec -i` with fixed program text and non-secret JSON arguments. They use `O_EXCL` and `O_NOFOLLOW`, touch only the test robot's `home/.codex/auth.json`, and print codes, never raw output. | Same Podman installation and notices as the row above. A missing Podman or a changed mount layout fails with exit 20. |

The deployed Ploinky, AchillesCLI, Explorer and shared AgentLib sources are project prerequisites verified against the release manifest, rather than dependencies installed by this test. The deployed native ALA backend and model access remain required application capabilities. Removing Playwright or Podman would remove the browser/native-runtime evidence required by this gate. There are no new vendored sources or Python dependencies.
