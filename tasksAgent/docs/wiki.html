Tasks terminology

Tasks agent

The Tasks agent manages the workspace backlog exposed through Explorer. Its tools read and mutate task records under the configured backlog root, while its plugins present those operations in the host shell without bypassing path or input validation.

Model Context Protocol

Model Context Protocol is the configured tool boundary used by the agent. Tool names and input schemas come from the local MCP configuration and execution remains subject to the agent's verified runtime authorization.

Ploinky

Ploinky starts the agent, supplies its runtime environment, and mediates authenticated invocation context. The agent does not treat client-declared identity as authorization.

Backlog

The backlog is the persisted task collection owned by the Tasks agent. Task identifiers, status changes, descriptions, and ordering are manipulated through the agent contract rather than by editing internal storage from the browser.

Path safety

Path safety confines task storage to the repository selected by repoPath. Backlog and history arguments must be absolute filesystem paths inside that repository, with the appropriate .backlog or .history extension. The agent rejects /.ploinky/... virtual paths, relative storage paths, symbolic-link escapes, and targets outside the canonical repository boundary before reading or writing.
