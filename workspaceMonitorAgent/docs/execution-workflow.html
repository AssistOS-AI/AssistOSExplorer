Execution workflow

Settings and history

An administrator invokes a settings or history tool through Ploinky. The wrapper reads the verified invocation metadata, checks administrator access, and then reads or writes settings.json or queries history.sqlite under the configured persistent storage root.

Live collection

Logs

For a log list, read, or search request, the wrapper checks the administrator and calls Ploinky's private /api/edge/workspace-logs route with a signed request. The result contains the requested live file or retained archive data; Workspace Monitor does not create a local copy of those logs.

Explorer surface

The Explorer plugin checks the browser's administrator projection and hides its toolbar item for other users. Opening the item changes the browser hash to workspace-monitor-dashboard; the dashboard then polls workspace_monitor_snapshot_get for fresh resource data and uses the other agent MCP tools for settings, history, and logs. It does not call Ploinky's localhost-only /status/data route.

Resource history and selected-runtime history automatically retry temporary gateway or network failures up to three times, after 300, 900, and 1,800 milliseconds. Live metrics continue independently. If history still cannot load, use Retry history to request the current selection and interval again; access failures instead require an administrator session. The dashboard shows a short error message rather than the raw gateway response. Changing the runtime or interval, clearing the selection, leaving the tab, or closing the dashboard abandons older history requests and stops their pending retries. These gateway retries do not apply to settings changes or other monitor operations.
