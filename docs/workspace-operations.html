Workspace Operations

Explorer is the primary workspace surface for browsing directories, opening files, selecting compatible previews or editors, and invoking contextual actions without leaving AchillesIDE. The current path is reflected in the application route, so a supported file or directory location can be restored after navigation.

File selection opens the appropriate text editor, Markdown editor, media preview, Office integration, or agent-backed view. Ordinary workspace paths use Explorer's filesystem tools. Paths under /Confidential are virtual resources and use the permissions and storage contract owned by DPU. Research acquisition and access-request controls preserve the selected DPU resource, display an immediate busy state, and refresh the resource preview when the authorized operation or confirmation flow completes. After acquisition, use Verify read beside any entry in Verified Files to perform a real bounded read through DPU and see the byte count and continuation state directly in Explorer.

File and Folder Management

The New menu creates a folder or file in the current directory. In /Confidential/Secrets, the file action is presented as New Secret. Creation controls are disabled when the current DPU-backed location does not grant the required capability.

Context menus provide Rename, Copy, Cut, and Delete for supported entries. Directories also provide Paste into and Upload here; files can be opened in a new browser tab. Administrators additionally receive Open Terminal Here, which opens the Explorer-owned terminal target chooser described below. Ordinary users do not receive the item, and Router authorization remains authoritative for direct requests. Delete requires user confirmation, and Explorer refreshes the affected directory and clears invalid selection or clipboard state after the operation.

Copy, cut, and paste use Explorer's ordinary filesystem contract and are unavailable for DPU-managed entries. DPU-backed rename, delete, upload, folder creation, file creation, and permissions controls appear only when the effective resource capabilities allow them. This keeps the same Explorer interaction model while preserving the owning service's authorization rules.

Uploads target the selected directory, or the current directory when no directory is selected. Ordinary uploads use Explorer's authenticated upload route; Confidential uploads are delegated to DPU and rejected when the destination does not allow new content.

Terminal Targets

Open Terminal Here sends only the canonical workspace-relative directory to Ploinky's same-origin, mutation-protected discovery route. The chooser lists Ploinky Box first. It then lists only running agents whose current runtime identity and live mounts Ploinky has independently proven can access the selected folder. Explorer does not inspect containers, infer mounts, or translate a path.

Each choice shows its server-provided label, detail, effective working directory, and read-only or read/write access for the selected folder. Agent choices also explain that the terminal uses the container's normal user, tools, environment, permissions, and credential context. A read-only badge describes this folder mapping, not the entire container.

Selecting a row directly opens /webtty/#launch=<opaque-id> in a new tab with no opener or referrer. The short-lived launch ID is not a container selector and is not placed in a query parameter or browser storage. A blocked popup leaves the chooser open. Refresh replaces the complete discovery batch, and cancel asks Ploinky to invalidate the unused choices. Explorer never sends a raw container identity, translated or physical path, shell, arguments, environment, user, or runtime flags.

Find and Replace

Find file searches workspace paths by name after at least two characters and can exclude comma-separated glob patterns. Selecting a result navigates directly to that path. The default shortcut is Cmd/Ctrl+P.

Find/Replace in files searches file content within a selected base path. Users can enable case-sensitive, regular-expression, or whole-word matching and can exclude files with glob patterns. Results retain file, line, column, and preview context so individual matches can be selected.

Replace Selected changes only selected matches. Replace All applies the active query to the selected scope and warns when the visible search result is truncated. Large replacements require confirmation, changed files are refreshed, and partial failures or timeouts remain visible in the result summary. The default shortcuts are Cmd/Ctrl+Shift+F for search and Cmd/Ctrl+Shift+R for find/replace.

The browser invokes the root-confined Explorer search and replace tools; it does not receive unrestricted host filesystem access. Private .data trees are excluded from default autocomplete discovery, and background search jobs are stored under .data/explorer/search-jobs. Explorer resolves private writers through one canonical .data/explorer boundary and rejects symbolic-link components before persistence.

Workspace Settings

The Settings modal combines user preferences with workspace-scoped integration controls:

  • Agents loads settings components declared by enabled agents and available to the current account.
  • Plugins enables or disables discovered workspace plugins within the host manifest whitelist.
  • Copilot lists discovered Achilles skills; its enable and disable controls are temporary and reset when the modal closes.
  • Administration is visible only to administrators and embeds the authorized administration panel. User and branding changes work on the local control origin and configured public agent origin. Local requests use an origin-bound administrative token; public requests refresh the router's protected administration cookie through an authorized user-list read. An expired proof is refreshed once without weakening server-side role checks. Loading, success, and error messages remain visible in the panel.
  • Keymap changes or clears shortcuts for file search, content search, replace, save, autocomplete, and Settings, and can reset them to defaults.
  • Editor controls code-editor auto-save. Auto-save is disabled by default and uses a configurable idle interval when enabled; an external file change still blocks the save and produces a warning.
  • Theme selects the global light or dark application theme.
  • Avatar stores the user's profile avatar in the browser, controls whether WebMeet adapts AxiFace automatically to the user's voice or uses a manually selected emotion, and exposes agent-avatar overrides only when the authenticated user can manage them.

The Marketplace lists available agents and repository sources. Administrators can install or remove repositories and enable or disable agents. Marketplace management works on the local control origin and configured public application origin. Explorer obtains a fresh router proof bound to the session and exact origin; public requests also bind to the selected application host and active routing generation. The router verifies administrator access for that application before any mutation; a missing, stale, or mismatched proof is reported as an error and does not change the workspace. The UI permits one agent mutation at a time, keeps the native runtime-mode selector stable during rerenders, and retains failures until the operator explicitly dismisses them. Each agent shows a normalized Disabled, Starting up, Running, Stopped, Failed, Paused, or Unknown state. Starting agents refresh automatically, and Configure is disabled until the runtime is verified as running. Live updates use the same labels, accessible status, and Configure readiness as a full refresh; stopping or disabling an agent disables Configure immediately without rebuilding the row, and outdated lifecycle details are cleared.

Both Marketplace tabs hide skills repositories (including mixed agent-and-skill sources), skill entries, and the repositories basic, cloud, container-image-builds, copilot-agents, demo, extra, security, and vibe, along with their agents. Repository aliases follow the same policy by source URL. Search, repository filters, enabled-agent counts, and refreshes include only visible entries. Repos offers Agent Repos and Others. These visibility rules leave installed repositories, enabled agents, and the skills subsystem intact.

Plugin state and agent-avatar overrides use Explorer tools or the owning integration. Browser-only preferences such as keymap, theme, profile avatar, and editor auto-save do not replace server-side authorization or agent configuration.

Explorer prepares the AxiFace pack catalog at /explorer/shared/generated/axi-face-packs.json for both Explorer and WebMeet. This generated file belongs to Explorer and is excluded from its source checkout. Pack manifests and rendering assets keep their existing /explorer/shared/vendor/axi-face/ URLs, and catalog preparation leaves the AxiFace checkout unchanged.

Normative settings requirements are defined in DS008 User Settings.

Safety and Ownership Boundaries

Explorer validates ordinary filesystem operations against configured allowed roots on every call. It does not translate a browser-visible path into authority outside those roots. Destructive actions require an explicit user action, and server errors remain visible instead of being interpreted as successful mutations.

Virtual resources and plugin actions keep their own ownership boundaries. DPU decides permissions for Confidential resources, while Git, SOPLang, WebMeet, Tasks, and other domain agents own their mutations and diagnostics.
