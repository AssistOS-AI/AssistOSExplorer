AchillesIDE

A secure, extensible workspace where files, editors, AI-assisted workflows, and specialized agents work together without giving up clear ownership or authorization boundaries.

People and AI agents need a shared workspace where they can work on the same project, use the same context, and collaborate without exposing credentials or protected data. Files, conversations, decisions, and domain tools should remain connected, while every action still respects the identity, permissions, and responsibilities of its owner.

AchillesIDE brings files, previews, editing, AI-assisted workflows, and specialized tools into one authenticated browser workspace. Explorer provides a consistent surface for working with the project, so users and agents can act on the current context without repeatedly moving information between separate applications.

Explorer owns the shared workspace experience, while each specialized agent owns its domain operations and protected state. The Ploinky router authenticates requests, and verified plugins connect Explorer to enabled agents. Before performing a protected action, the owning agent validates the caller and applicable policy, then returns only the result needed by the workspace.

UserPersisto supplies identity and account administration to applications independently of Explorer. Its My Account page is application-neutral. Explorer declares its product access explicitly; other applications do not inherit that declaration. The account provider contract defines the configuration boundary.

Workspace copilot

Open Copilot here in a directory context menu opens the selected directory in RoboTeam's ordinary robot named default. Explorer enables roboTeamAgent global no-wait, an agent of this repository (Ploinky identity AchillesIDE/roboTeamAgent); there is no separate AchillesCLI agent. Other robots have their own Open Chat action in RoboTeam. Independent CLI conversations can run concurrently, while Desktop and Browser retain one shared GUI container per robot.

Robot skills and skillsets are managed in RoboTeam. Explorer Settings does not provide Copilot skill controls.

Agents and Plugins

Explorer provides the shared workspace shell. The integrations below are declared by explorer/manifest.json or discovered from verified IDE-plugins manifests. Each owning agent remains responsible for its domain behavior, authorization, and protected state. Runtime-owned workspace data volumes live below .data/; .ploinky/repos is the single named source-state volume exception.

Fresh deployments require an AdvancedLanguageAgent checkout at the workspace root with its dependency-free CLI supporting --home, --cwd, and --MCPServers. Explorer enables RoboTeam globally so its default robot can use that workspace checkout for Copilot.

The QA workflow installs ALA from its default branch, verifies its exact clean revision, and checks its dependency-free package and executable CLI. Its preflight verifies the required help options before starting the Explorer runtime graph.

OnlyOffice, WebMeet and its LiveKit runtime, WebMeet Scribe (Meeting Secretary), WebMeet STT, and Umami analytics are disabled by default; the Umami and webmeet repositories are installed so Marketplace can offer them, and an administrator who opens the WebMeet toolbar plugin enables WebMeet on demand; other users see an error until an administrator enables it. An administrator can enable each from Marketplace. Office editing requires OnlyOffice; automatic meeting notes require Scribe. The current Secretary uses browser SpeechRecognition and does not require the separate STT service.

Live Media Runtime

LiveKit Server runs as webmeet/liveKitServerAgent from the webmeet repository. WebMeet enables this runtime (Explorer does not), so it starts only with WebMeet. It owns Redis, LiveKit Server, Egress, and private health. Its pinned image, readiness checks, .data/liveKitServerAgent/ storage, Router routes, and fixed UDP 7882 media mux define its runtime boundary. The default stack requires no separate media-runtime repository or basic installation. Skills Explorer deployment retires existing media registrations through Ploinky before source update, verifies old runtime absence inside the owning Box, and preserves agent data. Failed migration evidence remains available for recovery and retry.

Explorer-Owned and External Entries

The help plugin is owned by Explorer and is covered by the runtime plugins guide. The manifest also enables RoboTeam and Soul Gateway, both held in this repository, as supporting dependencies; Umami is installed but not enabled. A fresh ploinky start explorer does not download or start a local model: the local Soul Gateway seeds a restricted free OpenRouter provider with the tiers fast, code, plan, write, deep, ultra, and web-assist. It uses a bundled free-only credential whose daily quota is shared by every installation using it, requires internet access, and is not available offline. Administrators can replace the credential in the admin-only Soul Gateway settings dashboard. OpenCode's free models are available through the optional legacy-agents/opencode-free agent, which ploinky start explorer does not enable; to add it to a workspace, run ploinky enable agent legacy-agents/opencode-free from the workspace root. The agent wraps the unmodified OpenCode CLI; once enabled, Soul Gateway discovers it like any other agent and adds it to no tier by default: plain-text chat only, no tool calls and no images, one answer per request delivered as a single chunk after several seconds, a free quota shared by every installation that uses the bundled key, and prompts subject to the free models' data-use terms. Native OpenCode execution through RoboTeam's installed OpenCode CLI is unchanged. Ploinky core supplies the administrator-only WebTTY surface through the selected Explorer host. Explorer owns its folder target chooser, while Ploinky supplies safe Box and live-agent choices and remains authoritative for runtime identity, mount access, translated working directory, and launch authorization. Those dependencies own their documentation and runtime contracts.
