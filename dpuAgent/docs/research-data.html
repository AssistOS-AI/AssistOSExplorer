Research Data and Controlled Processing

The DPU registers exact, attributable research resources, mediates Hugging Face acquisition and EDC negotiation or transfer, provides ACL-controlled access to verified files, and submits confirmed federated jobs to an available NVFlare backend.

Flow

Discover → inspect facts and policy → confirm external effects → run an actor-scoped idempotent job → stream and verify revision/checksums → atomically publish local data → consume it through bounded DPU reads → append provenance.

Explorer

Research Data and Jobs are virtual records, not ordinary folders. The standard Tools menu opens DPU Research WebChat even when Research Data is empty. Resource previews expose FAIR evidence, verified files, acquisition, access request, sharing, permission, provenance, and DPU Agent actions. Run Federated appears only for a federated resource when an enabled and identity-verified NVFlare backend is available. Run Secure appears only when a concrete secure backend has passed identity and attestation checks. The runtime plugin reuses Explorer cards, buttons, status badges, action groups, standard confirmation and permission modals, settings tabs, fullscreen control, and custom-select. Local CSS is limited to DPU-specific structure and responsive layout. Data Sources presents separate Hugging Face and EDC panels with provider-specific inline add and edit forms inside a stable-size, internally scrolling dialog. Administrators configure only the implemented connection fields and select a DPU secret reference; the active panel fixes the provider type, and credential values are never copied into source state.

DPU Research WebChat signs in through the workspace's Explorer SSO session, and the router keeps a separate runtime for each user, so one user's results and chat history never reach another. The agent accepts only router requests that carry the signed per-user runtime scope and serves one verified user per process; launch flags and environment values never choose the actor. The WebChat entry point reads each router envelope as soon as it arrives on the persistent runtime pipe. It verifies the envelope-bound router request, derives the actor without exposing the token to the model, and gives the planner the exact DPU tool catalog from mcp-config.json. Planner calls and MCP calls share the same validation, authorization, audit and domain dispatch. DPU tool decisions use the Achilles Markdown envelope, and the prompt section must contain exactly one fenced json block with one schema-valid object and no surrounding prose. Raw JSON, malformed JSON, arrays and untyped fences fail closed. Provider-specific searches use providerTypes; exact DPU source UUIDs must come from DPU results. If a recognized provider label is mistakenly placed in sourceIds, DPU safely moves it to the provider selector and executes one corrected search without another model turn. Unknown labels remain recoverable and perform no provider operation. Hugging Face discovery translates Romanian-language intent into a Hub language filter and ranks the expanded candidate pool by language, text modality, and declared size category before applying the result limit. If the planner receives empty provider content after a completed search, WebChat returns that verified DPU result deterministically and records a redacted diagnostic instead of replacing it with a generic failure. The entry point handles the internal /tasks discovery command locally with an empty task list and never forwards slash commands to the research LLM. Presentation visibility is preserved, and a request failure is isolated so later messages remain usable. It does not wait for the pipe to close between messages; end-of-file input is reserved for one-shot CLI and MCP calls.

Security boundary

Explorer is presentation only. Actor identity and invocation scope come from verified authentication, credentials come from DPU secrets, and provider policy remains authoritative. Physical storage paths are not returned to clients. File list, stat, and base64 read-range operations re-evaluate the resource ACL and reject paths outside the verified manifest, traversal, symbolic links, and chunks larger than one MiB.

Execution Boundary

A compute backend remains disabled until its connection and identity test succeeds. NVFlare submission requires at least three local-only participant resources, secure aggregation, a passing privacy assessment, and actor-bound confirmation. Successful jobs create protected derived model resources with participant and job provenance. Output release requires a separate confirmation. Secure execution uses the same job boundary and fails closed until a provider adapter supplies verified identity, attestation, policy, submission, status, and cancellation behavior.
