Soul Gateway Documentation

Soul Gateway is the Ploinky-managed gateway that gives agents and authenticated users a single model interface while centralizing model selection, provider credentials, request policy, failure handling, and operational visibility. Callers use OpenAI Chat Completions, Anthropic Messages, OpenAI Responses, or OpenAI-compatible embeddings endpoints without owning provider-specific routing logic.

The gateway authenticates the caller, converts supported inputs to a canonical request, resolves an alias, direct model, or cascade tier, runs configured middleware, leases provider credentials, and returns a protocol-specific buffered or streaming response. Configuration and operational records persist in embedded SQLite.

Repository and runtime

src/index.mjs starts the process, while src/bootstrap.mjs configures the runtime snapshot, service catalogs, background jobs, and HTTP routes. Public request handling lives under src/runtime/route/ and src/runtime/execution/. Provider adapters live under src/runtime/backends/; management handlers live under src/management/; persistence lives under src/db/.

The Ploinky manifest mounts persistent data at /data, listens on internal port 7000, publishes public inference and health routes through the Ploinky Router, and protects management routes with authenticated Router identity. The standard compatibility tiers are fast, plan, and deep.

Coding style and tests

DS001-coding-style is the canonical source for coding style, module boundaries, file-size guidance, and test organization. JavaScript uses ES modules and four-space indentation. JSON and YAML use two-space indentation.

Unit tests in src/test/unit/ isolate route, execution, policy, provider, management, discovery, and observability contracts. Integration tests in src/test/integration/ verify the HTTP boundary and embedded SQLite behavior. Run npm test for the complete suite or npm run test:unit for unit coverage.

Terminology and imported tooling

wiki.html is the canonical source for Soul Gateway terminology. This repository does not distribute agent skills as product functionality. Workspace-provided or imported skills remain development tooling, and downstream projects keep skill-specific documentation inside the imported skill folders rather than adding it to the host project's documentation set.
