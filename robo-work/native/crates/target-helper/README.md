# rw-target-helper

The RoboWork target helper of plan section 5.6 ("Target helper and private descriptor seam", "Receipts, fencing and cleanup"), against the frozen T0 contract (base + A1..A11: sections 2, 8, 9 and 10). Slices P2, P6b and P8 of `proof-target-implementation-sequence-2026-10-29_claude.md`. Dependencies: `libc` and the workspace's `rw-proto` (the v1 keeper wire schema and frame codec, since P8 a normal dependency), both already vendored and locked. No new third-party crate.

## Binary

| Command | Role |
|---|---|
| `rw-target-helper journal-init --root <dir>` | Provisioning (Ploinky, P3): creates the journal store (since P8 with the witnessed keeper attempt store `journal/keepers/`) in the provisioned directory under an identity minted from the kernel CSPRNG (an existing store is reported, never overwritten); prints `{journalStoreIdentity, device, inode}` for Ploinky to record. A lost journal provisioned again always gets a new identity |
| `rw-target-helper serve --mailbox <socket> --journal-root <dir> --store-identity <Id> --helper-incarnation <Id> --secret-file <path>` | Target side: first consumes the single-use ticket-secret file (`launch`; refusal: `invalid_request`, exit 78, before the journal or the mailbox is touched), then opens (never creates) the journal, reconciles every unsettled record (stop delivered where possible; journaled exited only when absence is verified, else left `stopping`; `startup_reconciled` event), binds the mailbox 0600 and serves one connection at a time, polling the mailbox and every keeper descriptor (at most every second) between connections. Every connection runs the A11 handshake with the consumed secret as the ticket key (kid `hti1.<incarnation>`), then authenticated frames (`peer`). The launcher is the keeper supervisor; without the keeper binary mutations refuse `keeper_unavailable` before any journal write. The ready line names the key (`session`: `helper-ticket-secret`) and the launcher (`keeperLauncher`: `keeper-supervisor`) |
| `... serve ... --proof-fixture-session [--proof-fixture-keeper]` | `proof-fixture` build only (a default build exits 64): the secret file is still required and consumed, but the public fixture ticket key replaces it (`session`: `proof-fixture`). The launcher stays the keeper supervisor. The test-only `--proof-fixture-keeper` replaces it with the launcher that launches nothing (host round-trip tests; the rwtarget launcher does not pass it since P8) |
| `rw-target-helper worker-peer --mailbox <socket> --probe` | Worker side: connects, records the target's kernel credentials (diagnostics only), sends one probe frame with one descriptor (no bootstrap), reads at most the target's challenge and its handshake refusal (`refusedCode`, an enumerated spelling or `refused`) and expects the close |
| `rw-target-helper worker-peer --mailbox <socket> --session` | Worker side (decision B4): prints the challenge, reads `{op:"bootstrap", ticket, sessionKey}` from stdin (the session key never in argv or environment), then `{op:"frame", messageKind, body}` lines, printing each validated reply with its raw frame. A helper refusal is printed only as an enumerated code or `refused` (A11.6). Proof-fixture faults: `{op:"bootstrap-drop", ...}` (lost `accepted`) and `{op:"drop", ...}` (lost reply) |

A failed mailbox `connect` is `connect_refused` (missing path, permission, no listener, not a socket, anything else) or `connect_timeout`, never a journal code: nothing was sent.

Exit codes: 64 usage, 69 not Linux (mailbox roles), 75 journal or mailbox unavailable (including a refused connect), 78 ticket-secret file refused (`serve`), 2 session refused (worker peer), 1 other failure.

Feature `proof-fixture` (off by default): the fixture ticket key, the `serve` fixture switches and the test-only fixture launcher. Keeper launch is never gated by it. Ploinky provisioning now delivers the per-helper-incarnation ticket secret (`control/helper-secret`, consumed by every `serve`), but registers no Router mint route yet, so the worker-side fixture minter (`robo-work/tests/g7/fixture/rwworker/fixtureMinter.mjs`) still signs with the public fixture key and a fixture run selects that key with `--proof-fixture-session` (the consumed secret is then dropped unused): a departure from the authority model, valid only as proof-fixture evidence.

## Documented differences from `journalModel.mjs`

Coordinator decision (2026-10-29): for the phantom cursor and the chunk budget the native behavior is adopted; the oracle is to be aligned later.

| Case | Model | Native |
|---|---|---|
| Retried `prepare` of a stopped record that was never created | creates it, reports `prepared` | no create; `stopping` receipt (oracle owner disposition pending) |
| Refused `input` that opened a new connection | phantom cursor `{0, acknowledged}` | nothing persists (adopted) |
| Input chunk history | unbounded | refused (`capacity_exceeded`) once the record's projected settled size (every resource released with evidence, maximal counters and times, acknowledged cursors) would exceed the 256 KiB per-record budget, so a record can always be stopped, exited, released and retired (adopted) |
| Release hook failure part-way | not modeled | each successful resource release is persisted (no revision change) before the next; a retry calls the hook only for the rest. The hook must still be idempotent per (key, resource) |
| `stop` with a non-object request | `state_corrupt` (TypeError) | `invalid_request` |
| Stop of a `reserved` record | stop effect only if created | stop hook always called (create may have happened before a crash); idempotent |

## Slice P8 departures and limits

| Item | Status |
|---|---|
| Absence of an earlier helper process's keepers | Verified locally only for this boot and PID namespace (exact pid/start-time checks of every requested role; survivors are killed through a pidfd) or for another boot (`boot_id` differs). A replaced container whose PID namespace inode was reused takes the same-namespace branch, which is sound (reuse implies the old namespace was destroyed) and settles `exited`. Records of another PID namespace, or with an unknown namespace or boot, a missing attempt record or an unverifiable store, rest in `stopping` with the stop recorded as delivered (no later create); release refuses `absence_unverified`; quarantine is the operator path and frees the tracked execution's descriptors and capacity slot once its keeper child is reaped. A Router/Ploinky runtime attestation of the exact old instance (matched against the attempt record's incarnation, cgroup and host name) is a future slice. No inspect, name or registry evidence is used |
| Lease renewal | The accepted handshake is the renewal (fresh helper nonce, strictly greater epoch, 5 s challenge); no `renew-challenge`/`renew` frames. Transport EOF does not end a lease (the worker closes its session after every step); the 15 s deadline does |
| Workload HOME | An execution-private directory below the runtime base (P9 imports the robot HOME) |
| Workload output | Kept in the execution directory for the operator (P9 adds the channels); never sent to the worker |
| Accounting | PENDING (not closed by P8): per-execution process, memory, CPU and descriptor accounting (the keeper's `cgroup` kind still refuses). `executionsPerTarget` and the output bound are enforced |

## Not in this slice

Concurrent sessions (one at a time, 300 s idle timeout); a worker-side mailbox bind in Ploinky provisioning; the Router mint route (the P4 minter is a library); descriptor import and the five channels (P9); `input`/`connect` frames. Gate additions for `scripts/gates.sh` (lock set, vector identities, ELF check of `rw-target-helper`) are coordinator follow-ups.
