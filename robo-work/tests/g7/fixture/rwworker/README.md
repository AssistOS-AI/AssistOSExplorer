# rwworker (proof-fixture worker host, slice P6b)

The worker side of the proof-fixture G7 round trip with the `rwtarget` fixture. Decision B2: a worker host composed from production `robo-work/server/` modules inside a fixture worker image counts as the T2 worker image for proof-fixture evidence; the packaged production worker agent stays a T3 deliverable. Decision B4: the mailbox seam is the native worker-side peer, `rw-target-helper worker-peer --session`. Nothing outside `tests/g7/fixture` and `tests/g7/selftest` may import these files (T1-10).

| File | Content |
| --- | --- |
| `workerHost.mjs` | Exactly one ticket source per host: the fixture key (`ticketKey`) or the Router (`mintTicket`, see below). Admission through the qualification store and `requireExecutionTarget`, channel epochs per A11.2 (the attempted epoch is recorded before each bootstrap; the next request is `max(attempt, accepted) + 1`), helper codes reduced to known spellings (A11.6), the TargetBinding, revalidation of the admitted binding before commit, prepare/commit/lookup over the native peer, every reply frame re-validated with `validateTargetFrame`, receipts reconciled and start outcomes classified with `receipts.mjs`. Durable fixture state in one private file |
| `fixtureMinter.mjs` | PROOF-FIXTURE stand-in for the Router mint route and for the session-key hand-over, used only by the default mode in the selftest (the live fixture runs `--router-tickets` against the rwtarget helper, which verifies with its per-incarnation secret): signs tickets with the public fixture key (`native/crates/target-helper/tests/vectors/session-fixture-v1.json`). Every minted ticket is checked with the production `validateHelperTicketClaims` before it is presented |
| `main.mjs` | One step per invocation (`admit`, `define [--kinds k1,k2] [--workload <json>]`, `prepare [--drop]`, `lookup [--lose-accepted] [--needle-fd <n>]`, `commit [--revalidate]`, `revalidate`, `stop`, `release`, `rebind`, `state`, and with `--router-tickets` also `advance [--prior-generation <Id>]`); prints one canonical JSON result |
| `Containerfile` | The `rwworker` image: Node 24 (the agent base Ploinky uses, by digest), the modules above, `server/helperTicketClient.mjs` and `server/sourceProtectionClient.mjs`, the operator record tool, the session vectors and the default static `rw-target-helper` |

## Router tickets (`--router-tickets`, mint route spec 2026-10-30)

| Item | Behaviour |
| --- | --- |
| Ticket source | `mintTicket` is `server/helperTicketClient.mjs` over Ploinky's agent transport `/Agent/lib/helperTicketTransport.mjs` (`--agent-lib` overrides the directory): the private helper-ticket operation, authenticated by the private agent assertion from the identity Ploinky put in the worker container. No fixture key is loaded. The client checks that the decoded claims are exactly the request before anything uses the ticket |
| Session key | The Router's `sessionKey` (A11.5), decoded once; never derived from a key here. The ticket and the key are held in memory only and reach the native peer only on its stdin; the key buffer is zeroed when the session closes. Neither is written to argv, the environment, output or the state directory (R3) |
| Worker generation (Q3) | `advance` registers a fresh generation in Ploinky's source-protection store over `/Agent/lib/sourceProtectionTransport.mjs` (`priorGeneration` is the last one this state directory registered; `--prior-generation <Id>` names it for a state directory that has none yet, and the store compares it with its pointer). The body is recorded before it is sent and resent unchanged after an unknown outcome. `admit` and `rebind` refuse `worker_identity_mismatch` unless the facts' worker half is this worker's Ploinky identity (`PLOINKY_AGENT_ID`, `PLOINKY_AGENT_INSTANCE_ID`, `PLOINKY_AGENT_ENABLE_GENERATION`) and the advanced generation |
| Epochs (A11.2) | Unchanged: the attempted epoch is recorded before each bootstrap; the request is `max(attempt, accepted) + 1` with `previousChannelEpoch` the last accepted one |
| Lease | `leaseId` is a fresh random 128-bit opaque id per lease (admission, recovery `rebind`) |
| Retries | `caller_mismatch`, `target_not_eligible`, `secret_unavailable`, `capacity_exceeded` (also a 429) and a 503 are transient: retried after 150, 400 and 900 ms on the same helper nonce and epoch while the elapsed time stays within 3 s of the challenge, then once more on a fresh session after 1 s (new nonce, new recorded attempt epoch). Every other refusal or failure is terminal |
| Refusal text (A11.6) | Mint codes are printed or persisted only as a minter code, `forbidden`, `invalid_request`, `ticket_binding`, `router_unavailable`, `mint_unavailable`, or `refused`; error messages are never propagated. Results carry `ticket: {source, mintAttempts, kid, jti, exp}` |
| Leak probe (U7/R3), TEST-ONLY seam | Never used in production operation. Refused (exit 1, nothing written) unless all hold: `--router-tickets`, the command is `lookup`, and `<n>` is an integer of at least 3 naming an inherited FIFO; the needles are written once and the fd is closed. `lookup --needle-fd <n>` counts, while its session is live, matches of the session key and ticket in the worker's own and the peer's argv and environment and in the state directory (counts only, with a positive control computed by the same counting function; unreadable state files are counted apart as `stateUnreadable`), then writes the needles once to fd `n`, which must be an inherited pipe to the operator's scanner. A sink write that fails is recorded as `scan.sink: "failed"` and makes the lookup a refusal (`stage: scan`, `code: scan_sink_failed`, exit 3); the session is closed and its key zeroed either way |

## Proof-fixture departures

| Departure | Why | Production replacement |
| --- | --- | --- |
| The worker holds the ticket signing key (default mode, selftest only) | The selftest keeps the public fixture key for a helper it starts with `--proof-fixture-session` | Live fixture: `--router-tickets`, the Router mint route and the per-helper-incarnation secret shared only by the Router and the helper; the rwtarget launcher starts the default helper build without `--proof-fixture-session` |
| Session key derived from the ticket secret (`native/crates/target-helper/src/session.rs`) | Recorded departure from T0 section 8 (amendment A11.5) | None: accepted by A11 |
| Release evidence digests are worker-computed stand-ins naming the ended receipt (slice P8) | No worker-side resource ledger yet; the helper verifies every absence itself before it records a release | S1 worker ledger evidence |
| `rebind` re-binds the same execution to a replaced target for lookup, stop and release only, under a new recovery lease (slice P8) | Recovery of an execution whose target was replaced | The worker's recovery authority (T3) |
| The worker reaches the mailbox through an operator `podman run -v <instance mailbox>` inside the Box | Ploinky binds the mailbox only into the target, and refuses manifest volumes outside the workspace inside a Box | A worker-side mailbox bind in Ploinky provisioning |
| Source-protection, attestation and HOME facts are operator-supplied | Not produced by Ploinky for this fixture yet | Ploinky discovery and source-protection facts |
| The worker's durable state is a file, not the S1 store | Fixture scope | S1 worker state |

## Tests

`robo-work/tests/g7/selftest/rwworker.test.mjs` runs the host end to end against `rw-target-helper serve --proof-fixture-session` on the host, and in `--router-tickets` mode against a helper that verifies with its consumed per-incarnation secret, with a test Router (the production client over a transport holding that secret) and leak scans of the state directory, the peer's argv and environment and every result. It needs `RW_TARGET_HELPER_FIXTURE_BIN` (a `--features proof-fixture` static build) and optionally `RW_TARGET_HELPER_BIN`; without them its tests are skipped, which is not a pass. Use a short `TMPDIR` (AF_UNIX path length).
