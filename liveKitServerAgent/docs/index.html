LiveKit Server Runtime Documentation

AchillesIDE/liveKitServerAgent runs a pinned multi-architecture image and supervises Redis, loopback LiveKit signaling/API, LiveKit Egress, and private health. After Router authority attestation, container startup generates private configuration from the mounted immutable topology; pre-attestation host hooks receive no Router locator or topology environment. When that topology declares media, LiveKit advertises its literal globally routable unicast public IPv4 and ignores local overrides. A topology without media enters local deployment mode: the manifest-declared optional PLOINKY_MEDIA_PUBLIC_IP selects an explicit usable host or LAN IPv4; absent that, the manifest-resolved PLOINKY_HOST_REACHABLE_IPV4, normally supplied by deployment-time detection, is preferred; otherwise startup discovers a usable container interface. Operator configuration may replace that detected hint through normal optional manifest env resolution. This local mode is not production or cross-network release evidence. LiveKit owns the single box UDP mux on 7882 in either mode.

Readiness and recording

Public signaling is routed through the public Router service. Twirp administration is routed only through the private Router listener with authenticated policy and an exact current-generation caller assertion. Egress template/service 7980 and health 7981 are distinct, loopback-only listeners with semantic probes; readiness requires the exact supervised PID to remain live and both kernel sockets to carry the unprivileged egress UID. The pinned binary digest is verified before that exact binary is invoked, avoiding dependence on remapped /proc PID views or optional socket process metadata in nested rootless runtimes. The supervisor runs both PulseAudio and Egress as the image's unprivileged egress user, supervises all four runtime children, and grants that user access only to an ephemeral private config copy and the recordings mount. PulseAudio's runtime directory is the fixed tmpfs path /dev/shm/livekit-egress-xdgr; it cannot live on the container's fuse-overlayfs root, where PulseAudio fails to apply the ownership and mode it wants to its native socket, leaving it owned by root with mode 0755 so the unprivileged client is refused while the daemon still reports a complete startup. Egress's hard-coded /home/egress/tmp service/handler IPC path is not relocated: it remains the image's own directory on the container root, and startup only clears its contents so no stale handler socket survives a restart. /dev/shm/livekit-egress-xdgr is therefore the only fixed tmpfs path, and it is not configurable: startup removes that directory itself before recreating it so a pre-created symlink cannot receive the egress ownership change. The trusted recorder's Chrome process exposes its in-namespace host ICE candidate through a scoped feature override while external clients retain the exact active 7882 candidate; LiveKit does not enable global mDNS resolution or another media port. Release evidence requires a connected publisher plus a completed non-empty room-composite recording, so open listeners alone are insufficient. The upstream wildcard-health binary is rejected; activation requires the published multi-architecture digest of the commit-pinned loopback patch.

External relay

Relay service is external. Ploinky brokers short-lived relay credentials to exact authorized consumers; this agent contains no relay daemon, public TLS proxy, certificate process, or long-term relay secret.

Storage

All workspace-persisted media-runtime state is owned beneath .data/liveKitServerAgent/: generated configuration uses generated/, Redis uses redis/, and Egress output uses recordings/. The container paths remain /working-data/generated, /data/redis, and /data/recordings.
