Manifest And Runtime Configuration

The WebMeet manifest defines the runtime command, persistent data mount, guest-facing routes, supporting agents, and the environment shared by the default, development, and production profiles.

Runtime And Storage

SettingConfigured valuePurpose
Agent commandsh /code/scripts/startAgent.shStarts the WebMeet AgentServer process.
Persistent volume.data/webmeetAgent/data to /dataPersists encrypted room state outside the container filesystem.
WEBMEET_DATA_DIRRequired; manifest default /dataSelects the WebMeet store root. Runtime path resolution fails closed when it is absent.
WEBMEET_ROOM_PREFIXDefault webmeetSupplies the configured room-name prefix.
WEBMEET_AGENT_NAMEDefault WebMeetAgentSupplies the runtime agent name used by agent calls.

Secrets

VariableManifest contractPurpose
PLOINKY_WEBMEET_MASTER_KEYRequired generated secretWraps per-room encryption keys and must remain stable for the workspace.
LIVEKIT_API_KEYRequired shared generated secretAuthenticates WebMeet operations against the LiveKit deployment.
LIVEKIT_API_SECRETRequired shared generated secretSigns and authenticates LiveKit control-plane requests and participant tokens.

Workspace Roots

The profiles pass through ASSISTOS_FS_ROOT, WORKSPACE_ROOT, and PLOINKY_WORKSPACE_ROOT. The runtime resolves its authorized workspace context from Ploinky rather than documenting a workstation-specific absolute path.

Router Access

RouteAccessPurpose

/static-files/*PublicServes browser runtime assets required by the room loader.
/IDE-plugins/webmeet-tool-button/*PublicServes the Explorer plugin and its components.

Enabled Services

The manifest enables AchillesIDE/liveKitServerAgent from the same repository with no-wait. Startup ordering therefore does not imply that LiveKit has completed its own readiness checks. webmeetScribeAgent remains optional and disabled by default; enabling it waits for the same LiveKit runtime.
