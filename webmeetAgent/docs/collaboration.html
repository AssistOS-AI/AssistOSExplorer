Documentation / Collaboration features

Collaboration Features

The room interface combines realtime conversation, durable resources, shared visual workspaces, and collaborative documents without collapsing their distinct authorization and storage boundaries.

Audio And Voice Input

WebMeet defaults to a browser-local automatic voice pipeline for participants without saved preferences. It uses locally vendored RNNoise when supported, conservative adaptive gain and hum detection, standard browser processing as fallback, and local remote-participant volume normalization. Manual audio-control edits switch the draft from automatic to custom. Diagnostics do not persist raw audio.

When automatic avatar adaptation is enabled, LiveKit is authoritative for microphone publication, Mute and track availability. While that track remains available, a conservative browser-local energy gate maintains voice continuity across short changes in LiveKit active-speaker ranking, and Meyda refines active local speech to happy, confused or alert. Neither can override a muted or unpublished microphone. Active speech never selects the resting sleepy state. Muting or losing the microphone returns immediately to neutral, while sustained silence returns after the release interval. The controller publishes its final state through the existing LiveKit avatar projection channel for other participants. Audio samples and extracted characteristics stay in the browser; only the selected avatar state, intensity and speaking flag are shared. Selecting an emotion manually disables automatic adaptation until the user enables it again in Avatar settings. Avatar changes made outside a connected room are saved and shown locally; WebMeet publishes the effective avatar through LiveKit after the participant joins. Leaving or reconnecting stops the local analyser cleanly without blocking the room lifecycle.

The chat composer exposes browser speech recognition as push-to-talk input for RoboTeam commands. Holding the microphone control inserts the /robo prefix, displays interim recognition text, and enables transient Blackboard ordinals. Releasing submits through the same authoritative command path as typed input. This browser-scoped input does not alter the published LiveKit microphone, persist audio, call the scribe speech-to-text service, or create another WebMeet speech endpoint.

Chat And Room Resources

File-reference suggestions use one Explorer search response that includes file and folder kinds. Autocomplete does not start a separate metadata request for every match, keeping the browser connection capacity available for ordinary chat messages.

Chat messages and resources are durable room activity. Attachments accept files up to 15 MB from the picker, clipboard, or drag-and-drop. The ordered publisher creates the durable chat message and the selected Blackboard widget as one coordinated result.

The canonical /WebMeet/<room-folder>/ directory is the room resource root. SCRIPTA documents are direct children and uploaded assets are stored beneath assets/. Each asset directory contains one real file; WebMeet does not maintain metadata sidecars that must be synchronized with it.

Blackboard Workspaces

Blackboard belongs to the WebMeet room domain. webmeetAgent owns its authoritative workspace model inside the encrypted room payload, validates every read and mutation against room participation, serializes accepted changes under the room lock, and stores its revision and Undo/Redo history. Explorer hosts the plugin that renders the board, but Explorer does not own Blackboard state. LiveKit carries realtime update signals between connected participants, but those signals do not replace the persisted WebMeet projection.

Participants use Blackboard as the room's shared visual working surface. A room has one ordered Blackboard workspace containing multiple named boards. Each board can contain text, cards, shapes, images, files, embeds, polls, bullet lists, connectors, groups, and at most one SCRIPTA document widget. Participants can create, rename, reorder, activate, and delete boards; arrange supported widgets; group selections; connect shapes; copy or transfer supported content between boards; and use one global atomic Undo/Redo history for workspace and content mutations. The Blackboard header provides a visible Close control that returns the current browser to the participant layout without publishing a room visibility change.

Blackboard owns visual placement and collaboration metadata, not the underlying workspace file. For a file or SCRIPTA widget, WebMeet stores the room attachment, widget projection, geometry, active board, and safe participant-facing metadata. Explorer remains the storage authority for the actual file, canonical Markdown, and Automerge replica. This boundary allows the board to coordinate a document without silently becoming a second document store.

Lines and arrows can snap independently to four connection points on standalone widgets and complete groups. Connected endpoints follow move, resize, and rotation. Connections never span boards, and an atomic copy or transfer remaps only relationships contained in the moved selection.

RoboTeam Collaboration

RoboTeam is WebMeet's room-owned collaboration assistant and command-orchestration layer. Its purpose is to let admitted participants change the shared Blackboard and attached SCRIPTA content through the same authorized event model used by direct interface actions. WebMeet stores RoboTeam configuration and its logical agent record in the encrypted room payload. When enabled, the roster projects it as the non-media participant agent_robo_team; it is not a LiveKit audio or video worker and it does not own the Blackboard data that it operates on.

Participants can submit a typed or push-to-talk /robo instruction in natural language. WebMeet first binds the request to the authenticated room participant and captures a path-free projection of the selected board. One isolated, bounded MainAgent round uses the local blackboard-event behavior to translate that request into strict-schema canonical events. A deterministic /event command and a direct interface action skip natural-language interpretation but enter the same webmeet_event_command execution path.

The command result is not applied as arbitrary model output. WebMeet validates every event against the allowlisted Blackboard contract, rejects unsupported actions and identifiers, serializes accepted mutations, increments the workspace revision, persists the encrypted room payload, and then emits the participant projection. A semantic error returns explanatory text and leaves the board unchanged. Repeated command identifiers are idempotent, and participant-facing audit entries omit workspace paths, owner hashes, transport identifiers, private board identifiers, and client-supplied provenance.

RoboTeam settings are administrator-controlled and include the assistant identity and objective plus sections for Blackboard behavior, Meeting Notes, document building, moderation, bots, and adaptation. The active Blackboard command path does not grant those settings authority over LiveKit media, Explorer files, or room authorization. Meeting Notes is performed by the separately delegated webmeetScribeAgent. The attach, list, and detach lifecycle manages the logical Ploinky RoboTeam record and does not create an optional LiveKit AI participant.

SCRIPTA Editing

SCRIPTA collaboration uses Explorer-owned Automerge replicas and stable document elements. Paragraph edits, participant changes, and Meeting Notes revisions merge through incremental CRDT operations instead of competing whole-file overwrites.

Each Blackboard board can project one native SCRIPTA document widget. Document mode renders the document title, all chapters, and only the active variant text and images for each paragraph. Selecting a paragraph switches that same widget to paragraph mode, which is WebMeet's Multi-Version Paragraph Widget experience. Paragraph mode shows the document and chapter context, the current position, every available variant, voting controls, alternative creation, owner-authorized editing and deletion, and AI reformulation. It is a mode of the document widget rather than a second Blackboard widget.

Deleting the SCRIPTA widget from its Blackboard context menu removes only that board projection and clears the board's active document. The room document reference, Markdown file, and Explorer Automerge state remain available. Permanent document deletion is a separate, explicitly confirmed SCRIPTA document action and completes through Explorer's transactional deletion contract.

Document controls use shared WebSkel components, and adding a chapter or paragraph focuses and scrolls the new stable element into view after the realtime projection arrives.
