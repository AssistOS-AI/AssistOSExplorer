WebMeet terminology

WebMeet

WebMeet is the sovereign room control plane for room lifecycle, verified participation, encrypted collaboration state, shared resources, and explicitly managed room agents. LiveKit owns active media and presence; WebMeet owns durable room data and authorization.

Model Context Protocol

Model Context Protocol is the configured tool boundary used by the agent. Tool names and input schemas come from the local MCP configuration and execution remains subject to the agent's verified runtime authorization.

Ploinky

Ploinky starts the agent, supplies its runtime environment, and mediates authenticated invocation context. The agent does not treat client-declared identity as authorization.

Room-scoped guest

A room-scoped guest is an unauthenticated visitor whose router session is restricted to one webmeet:room:<roomId> scope. Possessing a room link does not grant room management or access to another room.

LiveKit

LiveKit is the active audio, video, screen-share, participant-presence, and data-channel service selected through WebMeet's private topology contract. Its runtime state is not the durable WebMeet room directory. WebMeet also uses LiveKit active-speaker signals for automatic AxiFace speaking and listening presentation; richer voice characteristics are analyzed only in the participant's browser.

Blackboard

Blackboard is the shared visual workspace owned by a WebMeet room. Participants use it to organize text, cards, shapes, images, files, embeds, polls, bullet lists, connectors, groups, and an attached SCRIPTA document across an ordered set of named boards. The active board is shared room navigation, while each browser may independently open the Show all preview surface.

webmeetAgent owns the authoritative Blackboard model, authorization, revision ordering, mutation serialization, and atomic Undo/Redo history. The privileged workspace is persisted in the encrypted room payload beneath the room-owned RoboTeam record. Explorer hosts the rendering plugin and remains the authority for attached workspace files and canonical SCRIPTA state. LiveKit distributes realtime notifications, but neither Explorer's rendered component nor a LiveKit event replaces the persisted WebMeet projection.

Blackboard stores visual and collaborative state: board order, active board, widget projections, logical geometry, groups, connectors, shared semantic focus, and history commands. It does not become the canonical store for an attached file. Connections are board-local, and participant projections remove private paths, owner hashes, transport identifiers, and other privileged metadata.

RoboTeam

RoboTeam is WebMeet's room-owned collaboration assistant and command-orchestration layer. It exists so admitted participants can operate Blackboard and attached SCRIPTA content through direct interface actions, deterministic /event commands, or natural-language /robo instructions without creating separate mutation APIs for each interface. WebMeet stores its configuration and logical agent record in the encrypted room payload and may project it in the roster as agent_robo_team.

For natural-language input, one isolated bounded MainAgent round receives a path-free semantic board projection and returns strict-schema canonical events or an explicit semantic error. WebMeet then validates and executes those events through webmeet_event_command, the same authoritative path used by supported interface mutations. The model cannot write arbitrary room state, supply trusted provenance, bypass participant authorization, or directly edit Explorer files.

RoboTeam is not a LiveKit media participant and does not own Blackboard persistence. It has no microphone, camera, or independent media session. WebMeet owns the board and command transaction; Explorer owns attached files and Automerge replicas; and webmeetScribeAgent owns Meeting Notes reconciliation. The room-agent lifecycle manages the logical Ploinky RoboTeam record rather than an optional LiveKit AI worker. Administrators control RoboTeam settings, while admitted participants may request the supported room operations.

SCRIPTA

SCRIPTA is Explorer's structured collaboration model for WebMeet room documents and Meeting Notes. Explorer's canonical Automerge document is the working authority and Markdown is its durable portable materialization. WebMeet stores board-scoped attachments and presentation metadata only.

Automerge

Automerge is the conflict-free replicated data type library behind Explorer's canonical workspace Markdown state and the sanitized public SCRIPTA collaboration replica. Explorer validates and merges incremental changes, then materializes the converged state to Markdown. WebMeet opens authorized participant sessions and carries collaboration updates without writing the file directly.

TinyMDE

TinyMDE is the Markdown source editor embedded by Explorer for ordinary .md editing. It emits incremental text-range changes through the same Explorer Markdown CRDT authority used by structured and SCRIPTA editing; only the editor interface and operation type differ.
