Documentation / Execution workflow

Execution Workflow

WebMeet coordinates admission, room state, media credentials, realtime participation, and durable meeting activity through authenticated agent operations.

Room Entry

sequenceDiagram
  participant User as Participant browser
  participant Explorer as Explorer shell
  participant WebMeet as WebMeet agent
  participant Media as LiveKit service
  Explorer->>WebMeet: Open room with workspace identity
  WebMeet->>WebMeet: Authorize participant or room-scoped guest
  WebMeet->>Media: Request generation-bound join material
  Media-->>WebMeet: Signaling and relay credentials
  WebMeet-->>User: Room projection and short-lived token
  User->>Media: Join audio/video/data session
  User->>WebMeet: Presence heartbeat and room commands

Room entry combines WebMeet authorization with a separate LiveKit media join.

Authenticated users join with workspace identity. Public guest entry is limited by the router to one room-scoped guest session. The returned participant state and media token are tied to the admitted room identity rather than client-declared authorization.

Room Lifecycle

Room settings exposes Archive room for history-preserving retirement and a separate administrator-only Delete room action for permanent cleanup. Permanent deletion requires explicit confirmation, closes the LiveKit room through the generation-bound private route, and removes WebMeet-owned encrypted room state, participant and agent state, chat and Blackboard history, resources, room event logs, and matching workspace event references.

The canonical room directory is removed only when it is an ordinary empty directory whose stored identity matches the deleting room. A symlink, mismatched path, non-empty directory, generic LiveKit error, or store staging failure aborts the operation and rolls durable moves back. Explorer-owned documents and media are not recursively deleted through direct filesystem access.

Media Credential Refresh

Before relay credentials expire and after browser network transitions, WebMeet resolves fresh join material and performs a controlled LiveKit disconnect, recreation, and rejoin. Microphone and camera state are restored. An active screen share stops and requires the participant to press Share screen again because browser display capture requires fresh activation.

The approved rootless transport boundary fails closed when the managed bridge cannot reach the private Router. WebMeet does not fall back to a public Router path, a direct private target, host networking, a widened listener, or a forwarding sidecar.

Meeting Notes Reconciliation

Enabling Meeting Notes creates its workspace. Final browser speech-recognition segments enter a retry-safe directed LiveKit queue, and the first accepted transcript creates and attaches one empty SCRIPTA document when the active discussion has none. Concurrent heartbeats cannot allocate duplicate documents.

webmeetScribeAgent reconciles each revision from the configured document structure, bounded cumulative memory, uncompacted transcript, and Explorer's metadata-free current projection. Explorer applies the result as Automerge text operations against a captured snapshot, merges concurrent participant edits, restores private document metadata, and commits canonical Markdown without direct file overwrite. Revisions are serialized and the room bar exposes authoritative queued, analyzing, updating, and retrying states.
